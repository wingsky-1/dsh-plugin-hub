# checklists.md — S2 多维审查详表 + 专项清单

> 本文件是 SKILL.md S2 阶段的**硬前置读物**：进入通读 diff 前必须已读。
> 内容：A-F 六维详表 → 三个专项清单（按触发条件选用）→ 复现三档速查。
> 使用原则：每维都要落到「文件:行号」证据；只报有代码依据的真实问题。

## A. 正确性与边界（最高优先）

- **竞态三件套**：inflight 请求与状态切换的交错（切换后旧响应是否回填缓存/
  响应内新旧字段混搭）；fire-and-forget 异步落盘的乱序；定时器与卸载清理。
- **热重载/全局单例**：window 全局桥接、模块级 let 状态在 apply 重入时
  是否捕获旧引用、dispose 是否为空函数。
- **迁移/割接路径逐步走查**：旧数据 → 新格式的每一步（内存态、落盘时点、
  rename 备份、崩溃恢复、二次启动幂等）；特别警惕
  「先写新文件 → 再扫描同一目录加载」这类**同源双读**导致的重复。
- **新调用路径 × 既有函数交叉影响**：diff 聚焦评审易只盯新增代码；
  既有规则/函数被接到新数据流时，其误伤面与副作用会被放大，
  须对新路径触达的所有既有逻辑做重估。
- **防御对称性**：同一竞态/生命周期问题若在多个挂点、多条路径上存在，
  核对防护是否一致——一处有守卫、其余裸奔是最典型的「修了一半」信号，
  也是跨文件 diff 评审最易漏的形态。
- 数值边界：钳制上下限、NaN/非法值回退、空数组/空对象。

## B. 安全面（hub 红线）

- 全部路由 loopback 围栏 + 方法校验（403/405），含新增路由。
- 动态执行面：宿主 `import(用户 .mjs)`、客户端 blob import 执行——
  信任级是否在 README 安全节交代、失败是否只 warn 不阻断。
- **脱敏护栏覆盖面 = 出口全覆盖 + 绕过形态抽样实测**：
  - 出口侧：查单一出口汇合点，核对「所有出口字段均脱敏」声明是否属实；
  - 绕过侧：至少实测零宽字符/全角/HTML 实体等拆分形态；
  - 结论须区分「已知局限（文档诚实交代）」与「未交代缺口」，后者才计问题。
- 信息暴露：health/adapters 类元数据路由是否泄露绝对路径/内部结构（有围栏兜底，
  但属多余信息面，提轻微）。

## C. 兼容与数据

- 旧配置缺新键 → 默认行为不退化？旧客户端不读新字段 → 零影响？
- 旧数据文件版本割接：目标桶归属语义是否合理（历史数据被强制归入
  与来源不符的目标时，会产生「结构声明与实际样本不一致」的数据桶）。
- React externals / peerDependencies 语义正确性（optional peer + 宿主注入）。

## D. 文档-实现一致性（必查，最易坑用户）

- **README 里每个配置键名与 normalizeConfig/schema 实际读取键逐一对照**
  （高频翻车点：文档写在某命名空间/嵌套层下、实现却读顶层或另一层级）。
- README 命令、文件名、默认值描述与实现对照。
- 中英 README 配对同步；安全节标题是否符合仓库要求的 `## 安全模型`。
- package.json description/files 白名单与实际产物对照（示例目录是否随包发布）。
- **diff 中改动的命令/路径/路由先对照 main 定性**：README 中修改的 curl 命令、
  路径、端点，先 `git show main:<file>` 核实是「修正既有笔误」还是「行为变更」
  ——前者确认即可，后者要查实现，两者评审动作完全不同。

## E. 死代码与一致性

- 解析后无消费的配置键（grep 该键全部出现处）；计算后未使用的变量（空 if 注释块）；
  无调用方的导出；从未赋值的状态枚举值；恒真的 null 防御。
- 变量遮蔽（如 handler 内 `const res =` 遮蔽 http res）——功能对但易埋错，轻微。

## F. 测试质量（假绿识别清单）

- 弱断言：`>= N` 应为 `== N`；对 bundle 做 `includes("字符串")` 式断言
  （字符串在 ≠ 行为对，重构即碎）；只断言 `existsSync` 不断言内容。
- 时序依赖：固定 sleep 等防抖/异步（慢机 flake）——应改为事件/轮询条件等待。
- 迁移类测试必须断言**精确计数与内容往返**，否则恰好掩盖重复/丢失类 bug。
- **性能护栏输入形态假绿**：性能/回溯类护栏必须核对其输入是否覆盖声称防御的
  最坏路径；良性重复输入上的耗时断言视为无效证据——护栏恒绿 ≠ 无回溯退化。
- 新功能是否有对应 smoke 断言（仓库测试纪律硬性要求，含 403/405 围栏用例）。

## 专项清单一：正则/脱敏类 diff

触发条件：diff 含正则规则、脱敏/掩码、字符串匹配替换类改动。逐条核查：

1. **规则顺序约束是否注释化 + 占位符二次匹配幂等**：替换产生占位符后，
   后续规则或重复调用再匹配占位符是否会二次包裹（要求 `f(f(x)) === f(x)`，
   覆盖超时重发等重复调用路径）。
2. **lookbehind 排除类的副作用**：为防占位符误配而排除某字符，
   可能导致该字符包裹的真实目标漏报。
3. **字符类排除导致整体失配 → 半脱敏/明文残留**：目标串含排除类字符时
   整条规则失配，敏感信息以半掩码或明文残留。
4. **`\b` 与 `_` 等边界交互的「侥幸正确」**：识别依赖隐式机制才通过的用例
   （如下划线恰非 `\w` 边界），并要求注释固化该机制，防止后续重构破坏。
5. **惰性量词多起点回溯 × 同步调用路径 = DoS 面**：`[\s\S]*?` 类模式在
   宿主主线程同步路径上执行时，评估最坏输入形态的时间复杂度。
6. **误伤面用自然语言高频形态实测**：不只测攻击形态，还要测日常文案中
   含敏感词前缀的正常语句是否被误打码。
7. **先脱敏后截断的顺序**：截断窗口是否会把占位符腰斩、顺序是否锁定并有测试。

## 专项清单二：聚合包 / 生态联动（hub 仓特有）

触发条件：改动任一插件包。逐条核查 `dsh-plugins-all` 三处联动：

1. 聚合包 `package.json` dependencies 是否仍含该包；
2. 根 `cordis.patch.yml` insert 行是否需移除/重排；
3. README 插件表是否同步。

两条机制性风险：

4. **装配字典序风险**：聚合包装配顺序由 `scripts/gate/aggregate.ts` 按
   `readdirSync().sort()` 字典序生成——凡「A 包 apply 时检测 B 包痕迹」类
   兼容逻辑，字典序可能使检测必然落空（B 恰在 A 之后 apply ⇒ 标记不存在）。
   逐条给出「检测落空」的后果方向与兜底防线。
5. **退役断裂链**：「退役/删源码」步骤会断裂什么（`workspace:*` 解析失败 →
   聚合包无法构建发布）。删除动作前先画依赖反向图。

## 专项清单三：迁移/退役型 PR

触发条件：PR 含包级退役、迁移命令、版本窗口期、生态联动处置。

1. **版本窗口期**：main 上文档宣称的行为 > 发布物版本时，窗口期内照文档操作
   会被误导（release 校验只在 tag 时点发生，窗口期无兜底）。
2. **迁移命令须带前置校验探针**：如先探测新版标记路由确认生效后再移除旧包，
   或显式版本下限——防「先安装拿到旧版 → 再移除 → 能力静默丢失」。
3. **文档时态核对**：「已标记 deprecated」类现在时陈述在 PR 时点尚未发生的
   即为失实，应改将来时。
4. **过渡态矩阵逐一走查**：双装共存 / HMR 重载 / 热开关关闭等中间态下
   行为是否退化（尤其「新版本在过渡态反而不如旧版本」的静默丢失）。

## 附：P0/P1 复现三档速查（与 SKILL.md S4 双写，使用现场摘要）

按问题类型选档，不要默认上最重的第三档：

1. **纯函数直测**：Node ≥24 type stripping 直跑 .ts（`node --input-type=module -e` +
   绝对路径 import）；失败先排查 strip-types 语法限制（enum/namespace 等）再降档。
2. **build 后直跑 lib/index.js**：实例级行为；仅此档需要先 build。
3. **fake ctx + 路由注入**：路由级/围栏交互；fake req 必带
   `socket.remoteAddress`/`headers.host`/`sec-fetch-site`（否则围栏 403 假阴性）；
   async handler 要 await。

复现脚本与输出落盘到评审交付目录（脚本头部自描述：目的/前提/预期输出），
再清 worktree。复现失败先怀疑自己的验证路径，再下「误报」结论。
