# 评审维度矩阵（默认 6 维 + 可选维）

> 每维说明供 S1 裁剪与 S2 编写子 Agent prompt 直接复制。子 Agent prompt 必须给出
> 该维的「审查重点 + 证据要求 + 输出格式」；下列条目即为其最小答案集。

## A. 代码质量（任何评审必含）

**审查路径**（host 端 / client 端 / 脚本 / 测试逐文件检查）：
- 正确性与边界：事件语义（waterfall 是否不短路、serial 是否无 next）、状态机跃迁
  与中断/取消路径、时间边界（窗口合并、跨午夜、非法输入归一化）、文案截断与降级。
- 类型与严格性：`unknown` 归约是否正确、客户端 `any` 泛滥是否隐藏错误、两端
  常量（ROUTES）是否单点事实源。
- 错误处理与资源：SSE/连接清理、子进程（spawn/kill/超时）、定时器、事件监听 dispose、
  写队列串行化是否死锁/饥饿。
- 并发与竞态：per-key 状态表（Map）的清理路径、热重载解包重包语义（bind/字段污染）。
- 安全：命令拼接面（参数数组 vs shell）、通知/落盘内容是否泄敏、路由围栏
  （loopback 403/405）、读请求体限长、配置校验。
- 可维护性：职责、注释可信度、重复代码、内联样式 vs CSS 类、与仓库规范
  （干净模块/零依赖/共享层复用）符合度。
- 测试质量：smoke 覆盖充分性、关键缺口（资源清理/失败路径/浏览器行为）。

**证据要求**：每条发现必须带 `文件:行` 与代码引用；涉及宿主事件语义/枚举时
对安装版 `@deepseek-ai/dsh-*` 源码交叉验证后再下结论。

## B. 功能体验（任何项目必须含）

**重点路径**：
- 触达有效性：人不在浏览器前（页面隐藏/换 Tab/关 Tab）事件能否触达人；可见时
  不打扰逻辑；多标签页重复轰炸（需跨标签协调证据）。
- 文案质量：标题即结论、正文结论先行、行动建议；截断省略号；无标题/无耗时的
  降级文案区分度。
- 配置面板交互：开关语义分组、免打扰反馈（生效中/跨午夜/时区）、历史记录核查力
  （跨天/筛选/清空）、失败回滚、小屏可用性。
- 信息密度与噪声：事件风暴聚合、合并窗口语义（合并粒度是否误导）、堆积上限取舍。
- 权限与平台策略：手势请求时机、拒绝后引导、iOS/Chrome 差异感知。
- 降级通道：横幅/提示音/标题三层是否受开关控制、信息完整性（被顶替/被关）。
- 诊断：测试按钮能否证明「端到端弹出」、健康状态解释力、断线补偿。

**输出**：P0-P3 逐条（含「用户场景复现」，如"什么形态下用户会碰到什么"）。

## C. 新功能方向（用户要增强时）

**要求**：每条候选 = 功能名 / 解决的问题（用户故事）/ 实现要点（宿主、客户端各自
如何实现，指明接入哪个 DSH 事件或 API，引用现状代码锚点）/ 复杂度（S/M/L）/
价值（高/中/低）/ 风险或副作用；**必须带否决清单**（哪些是过度设计、为何不做）；
最后给 Top 5 路线图（按价值/成本序，分「下一版就做」与「远期」）。
**纪律**：所有候选必须基于现有架构与 DSH 事件可用性（以 pnpm-workspace catalog 锁版的 @deepseek-ai/* 官方类型层与同事插件
模式为证），不天马行空。

## D. 多端适配（插件带 UI/通知时）

**本项目硬约束**（必带入 prompt）：
- DSH 部署在 Linux 服务器，经**局域网 HTTP** 被 Windows / iPad / iOS 手机三种形态
  访问；另有本机 localhost 桌面与隧道（ssh -L / lan-proxy https）形态。
- 界面必须：响应式（320-414px 窄屏）、触控友好（≥44px 目标、无鼠标拖拽）、
  浅色/暗色双主题（`--dsw-alias-*` 变量 + 浅色回退，禁硬编码单色）。

**重点路径**：
- 窄屏：面板/横幅固定宽度溢出、fixed 元素不可滚动恢复、`dvh`/safe-area。
- 触控：拖拽是否只用 mouse 事件（表面 Pointer Events / touch-action）、开关可点区。
- iOS Safari/Chrome 差异：`Notification` 仅在 A2HS/PWA 存在（普通页无）、
  `isSecureContext` 局域网 HTTP 为 false、后台标签挂起（EventSource 不重连、
  Web Audio 暂停）、`webkitAudioContext`。
- 双主题：`--dsw-alias-*` 用齐性、JS 内联样式硬编码色清单、CSS 版本失效重建。
- 降级通道跨端：锁屏/切后台是否全失（关系核心卖点）。
- 宿主系统通知跨平台：Windows PowerShell toast（中文编码、需交互式会话）、
  Linux notify-send（无桌面/探测一次性）、macOS 默认无 notify-send（需 osascript）。
- 验证矩阵：哪些可 DevTools 模拟，哪些**必须真机**（iOS/iPad/Windows）。

## E. 安装影响（生态联动插件）

**双向分析**（都要给「可能性 + 严重性」）：
- A 被其他插件影响（受害）：插件依赖的主事件（approval/request、agent/status、
  agent/error、turn-stopping、internal/service…）被他人改语义/时序/短路；
  共享服务（如 userQuestions.ask）被其他插件包装冲突；热重载残留；UI 依赖
  宿主 DOM 结构漂移；宿主契约升级。
- B 影响其他插件（加害）：monkey-patch 可见性与 unwrap 互解；waterfall 链顺序漂移
  （谁先谁后决定语义）；全局浏览器副作用（document 监听、MutationObserver、title
  写入竞争）；DOM/样式类名与 z-index 冲突；`~/.dsh` 文件命名空间与并发写；
  子进程/EventSource 连接预算。
- 产出：**耦合面总表**（耦合点/方向/影响机制/受影响方/风险 高-中-低/缓解建议）
  + 高风险场景逐个展开（触发条件/波及面/现有防御/缺口/建议）+ 双向风险结论。

## F. 安全专项（涉密钥/凭据/网络执行/SSRF）

按 `secure-software-engineering` 的威胁模型视角：默认拒绝、最小权限、防御纵深、
修一类而非一例。特别检查：SSRF/webhook URL 任意化、令牌进出日志、子进程注入面、
配置文件权限位（0600）、通知/历史落盘敏感内容。

## G. 开源/依赖复核（可选插拔，用户要求「复用开源/自研核查/依赖治理」时启用）

**目的**：把全局规则「优先复用成熟开源库、实在没有才自写」落成评审动作，防
「该引开源却硬手写」「重复实现成熟库」复发。
**审查**：对插件**自研能力逐项**对照成熟开源库（node-notifier/execa/sse-channel/
conf/lodash/croner…），判定「保持自研 / 替换 / 借鉴」，评估引入成本（依赖内联、
零运行时依赖约束、平台二进制、进错端）与现状差异。
**输出**：`能力 × 成熟替代 × 引入成本 vs 现状 × 裁决` 表；结论一句话
（如「9 项全自研、唯一真弱点是进程树清理，不引库、原生补 ~10 行」）。
**纪律**：只裁决「是否该引」，不强迫替换；保持自研须说明为何不自写/权衡（零依赖/
自包含/定制语义等正当理由）。

## 验证方法学提醒（所有维度通用）

- 证据导向：任何断言必须「有文件有真相」，无法核实的写「未验证」。
- 复杂场景要求「能跑真实验证最小清单」，不要只凭 agent 自述。
- **证据分级**：P0/P1 断言**必须实测**（curl / 浏览器 MCP / node smoke，标注证据
  类型）；P2/P3 允许静态证据 + 标注「未验证」。详见 [verify-checklist.md](verify-checklist.md)。
