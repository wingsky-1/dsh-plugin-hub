# dsh-plugin-hub-refactor — 宿主端按域重构的方法论

> 与 `dsh-plugin-hub-dev` 的分工：那个管「怎么改现有代码」，这个管「怎么把代码重构成域」。
> 铁律的权威文本在 `docs/ARCHITECTURE-METHOD.md`；本文件是执行清单。

## 0. 什么时候值得重写

值得：业务判断散在事件回调里；模块之间直接取对方状态；新增一个能力要改三处以上、且
改动点不围绕同一个概念；同一份词汇在几处各写了一遍。

不值得：只加一个开关、只修一个 bug。重写的成本只有在「改动成本已经成为主要成本」时
才划得来——否则你是在用读者的时间换作者的时间。

## 1. 目标结构

```
<包>/src/
  index.ts                组合根：装配 + 包导出面
  client/                 客户端（干净模块，与宿主端解耦）
  server/                 宿主端
    <域>/                 一个功能域 = 一个目录
      interface.ts        域契约：本域对外承诺，下游从这里进
      deps.ts             依赖声明：本域对上依赖，Ports 类型的物理定义处
      impl/
        <块>/             实现块
          type.ts         块内形状
          index.ts        块实现
        index.ts          聚合器：只在多个块需要共同出口时才有
    shared/               包内共享层：跨域、无单一归属的语言
```

四条形态规则：

1. **域目录只有三样东西**：`interface.ts`、`deps.ts`、`impl/`。`impl/` 根只放聚合器与
   跨块的值文件，实现住 `impl/<块>/`。
2. **没有对上依赖的域不建 `deps.ts`**。没有出口就不造那个文件——空文件会被后来的人
   当成「这里应该有依赖」。
3. **块按「回答不同问题」切**，不按代码长度切。判据、路由、执行是三块，因为它们是三个
   问题；为了行数均衡把两个问题塞进一块，等于让它们共享一个修改理由。
4. **类型的物理定义在 `impl/` 的块里**，`interface.ts` 只 re-export。契约做收口，不做
   定义——两份定义迟早分叉。

## 2. 三条铁律

1. **`impl` 不得按值引用本域 `interface.ts`**。契约调实现是正常的，反过来会构成
   `impl → interface → impl` 的文件级值环，而模块粒度的门禁看不见它。**类型可以**
   （`import type` 不产生运行时边）。
2. **跨域运行时能力一律经 `deps.ts` 注入**。域之间不互相引用实现文件，也不通过上下文
   穿透取对方的东西。
3. **`deps.ts` 是纯类型面**。它声明「我要什么」，不提供、不实现。唯一的合法值是一个
   **标识符常量**（名字必须在值层存在，类型表达不了它）。

## 3. 依赖注入：能力按提供方分组

```ts
// 消费方的 deps.ts
export type XxxPort = Pick<typeof xxxApi, "doOne" | "doTwo">;

export interface ConsumerDeps {
  readonly xxx: XxxPort; // 一行一个提供方
  readonly yyy: YyyPort;
  readonly logger: LoggerPort; // 宿主能力，不属于任何域
}
```

- **`Pick` 收窄，越窄越好**：只写真正用到的那几个方法。收窄不到位是最常见的疏漏——
  声明里写着只读设置，端口却把整个读面递了过去，于是「只读」这句话不再有约束力。
- 组合根递**提供方的命名空间对象**（`xxx: xxxApi`），于是消费方将来多用一样能力时，
  装配那一侧一行都不用改。
- 端口传的是**能力**，不是算好的值：装配期取一次的快照会在用户改设置后失效，而它
  看起来与实时读取一模一样。
- **共享设施不入注入面**：跨包共享层里的纯设施（请求读取、回环判定之类）由用到它的
  实现块直接引。在注入面上过一道，只会让「本域依赖了谁」这张清单里混进不属于任何域
  的条目。

## 4. 组合根：只做三件事

1. **收窄宿主上下文**：把 `ctx` 变成各域要用的窄面（日志、事件面、路由口、服务出口）。
   域不直接触达全局上下文。
2. **按依赖顺序装配**：域只声明「我需要什么」，满足它是组合根的事。装配顺序即依赖顺序。
3. **注册生命周期**：具名释放动作，**逆序**执行（后装的先释放）。

纪律：

- 交付的是**能力**，不是算好的值。
- **未装配的占位要抛错**，不要给空实现：空实现会把「没装配」变成远处一个查不出原因的
  现象。fire-and-forget 的出口是例外——「没人听」与「没有出口」对它没有区别。
- 域间依赖也经这里注入（按提供方分组递命名空间对象），所以组合根读起来就是一张
  「谁需要谁」的表。**注释要与代码一致**：改了注入方案就改注释，否则下一批读者会按
  注释去理解一个已经不存在的行为。
- 装配与卸载要**成对**：每个域都有释放动作，且都复位自己的装配标记。不对称的后果是
  同进程第二次装配在某处抛错，而那看起来与该处以外的任何征兆都无关。

## 5. 类型与命名纪律

- 宿主端不出现 `unknown`、显式 `| null`、显式 `| undefined` 联合、匿名对象类型。
  收窄统一写 `cause instanceof Error ? cause.message : String(cause)`。
- **有状态的才用 `class`**，配一个导出单例（类不外放，外面 `new` 不出第二份）。
  无状态的用纯模块函数。
- **不用闭包工厂**：能力经构造签名摊开，而不是藏进词法环境。构造函数上写着「我需要
  什么」，闭包只写着「我恰好在那个作用域里」。
- **最小导出**：只导出有真实消费者的符号。「将来可能有人用」不是理由——多一个出口
  就多一份要同步的事实源。
- **名字只有一个物理定义**：对外的 ABI 名（服务名、事件名）做成 `as const` 常量，声明
  合并用**计算属性名**引用它（接口成员名接受字面量类型，所以常量能直接当键）。
  写死字面量同样能编译，代价是改名时漏改一处，而症状只在另一头出现。

## 6. 历史包袱：迁移独占一个域

- **版本迁移是一个独立的域**，它在各域装配之前跑（动的是磁盘）。
- 「旧版本把数据存在哪、旧键叫什么、哪个键要拆成两个」——这些**词只允许出现在迁移域
  里**。业务域不认识旧格式，也不该为历史包袱永久背一份依赖。
- 迁移最终落盘时，走**当前格式所属域的写面**，不要另开一条往磁盘上写的路。两条路对
  「什么算合法数据」的答案迟早会分叉，而分叉的表现是「通过迁移写进去的值和通过正常
  路径写进去的值，行为不一样」。
- **幂等是硬要求**：迁移失败不回写进度刻度，下次启动从同一步重跑，所以每一步都必须
  重跑安全。
- **需要等外部服务才能做的迁移**（旧数据寄存在宿主服务里）挂在「服务就绪」的回调上，
  不要硬塞进装配期的同步链；服务始终不来就不做，不拦住启动。
- **多个来源的优先级按时间新近定，不按读取难易定**。容易读到的往往是更旧的快照。

## 7. 工作流

1. **先方案后动手**：改动面 ≥2 个文件、或动公共接口与导出面时，先写方案（目标与验收、
   影响范围、选定方案、被否决的替代方案及原因），等确认。方案里写清「这次不做什么」。
2. **一个域一个提交**，每个提交都能单独读懂、单独回退。
3. **每步验证**：类型检查 → 构建 → 契约门禁 → 目录导入门禁 → 一个覆盖真实链路的探针。
   骨架期探针比单元测试更早可用：它能证明「链路是通的、只是行为还没实现」，而这是
   重写过程中唯一能证明的东西。
4. **注释写「为什么」**：不写过程式说明、不复述签名、不留注释掉的代码。**注释与实现
   不符是最坏的一类**——它比没有注释更贵，因为它会被相信。
5. **删测试要显式登记**：重写期间删掉的测试与随之放宽的门禁下限，要在同一批改动里
   记下待补。否则「测试变少」不会有任何信号，而门禁会安静地失去它的下限保护。
6. **越界即回退**：自动修复工具（格式化、lint `--fix`）会改动你没打算碰的文件。跑完
   先看 `git status` 的规模，把范围外的改动还原——「顺手修的」是 review 里最难发现的
   一类改动。

## 8. 重构之后的验收：复杂度与等价性

结构重构落地后，通常还有一轮「把复杂度热点压下来」的收尾。它的方法论与按域重写不同：
**先接缝、再抽函数，最后用变异与差分证明等价**。

1. **先接缝，再抽函数**。热点常常不是「写得太绕」而是「不可达」：平台分支只有本机那条能跑到、
   失败路径没有注入面。这时给块加一个端口（`impl/<块>/deps.ts`）把进程事实收进去，让几条分支
   都可达——覆盖率与 CRAP 会一起降下来。只为数字拆函数，是把成本推给下一个读者。
2. **口径分清**：`pnpm crap` 的阈值（`scripts/data/gauntlet.config.json`，覆盖满时 CRAP ≡ 圈复杂度）
   与 `tools/lint` 的 ESLint `complexity` 棘轮值是**两件事**——后者是「只拦新增劣化」的全仓上限，
   不是你的目标。验收必须用与门禁同源的规则量，并且**在 HEAD 版上把改前读数复现一遍**，
   否则「从 23 降到 13」只是自述：

   ```sh
   git show HEAD:<file> | node tools/lint/node_modules/eslint/bin/eslint.js \
     --config tools/lint/eslint.config.js --stdin --stdin-filename <file> \
     --rule '{"complexity":["error",16]}'
   ```

   （`tools/lint/node_modules/.bin/eslint` 是 shell shim，用 `node` 直接跑会 SyntaxError，
   要走 `eslint/bin/eslint.js`。再做一个对照：把阈值设成 1，确认文件真的被 lint 到。）

3. **抽函数的三条红线**：
   - **表达式逐字搬运**，不改判断语义。`>=` 与 `>`、`??` 与 `||`、可选键「不写」与「写空串」
     都是行为，别顺手「修正」。
   - **不引入写入式 `| undefined` / `| null`**（见 §5）。「可能没有」要么写成**有名字的两态
     判别式**，要么用**写出去风格**：助手收到目标对象、返回 `void`，把结果写进去
     （先例：`assignText` / `assignAuth` / `assignAuthHeader`）。可选**参数**用 `?:`。
   - **助手私有**，不进导出面。只有某个口径确实从外面读不出来时（例如 clamp 的产物只落在
     `AbortSignal` 的 deadline 上），才提成块内导出纯函数，并跑 `export-surface-snapshot`
     证明包入口零漂移。
4. **等价性证据分三级，交付里必须标级**：`A 差分实测`（旧实现与新实现喂同一组输入比较输出）
   > `B 定向变异`（改坏新实现的那一行，既有用例只红对应那一条）> `C 读代码论证`。
   只给得出 C 级的地方要写明「升到 A 级还缺什么」。值得做 A 级差分的几处：可选键的「有/无」、
   边界值（0 / 负数 / NaN / 超限）、异常路径的文案。
   **差分有覆盖盲区**：A 级差分只对「新旧都存在的函数」有效。整模块被重写的面（旧文件在新树里已无
   对应物）差分无从对照，必须另做一遍**基线源码级逐条对账**——把基线文件里对外可观察的行为逐条列出来，
   在新树里逐条找落点，找不到的就是被删掉的行为。实证教训：一次 1073 组 A 级差分全绿的按域重写，
   仍漏掉了「保留键写拒 / 通道未知键透传 / 推送体透传」三项已实现能力被静默删除，
   而两轮专家审计也都没抓到——**重写面积越大，越不能只靠差分**。
5. **一行改动一条红**：对每个抽出来的助手各做一次定向变异（优先改**判断**而不是改结构），
   确认红的是**用到它的那条用例**而不是一片。一改红一片说明用例与被测函数的边界不清，
   先修用例。
6. **实验在探针 worktree 里做**，做完 `git worktree remove --force` + `prune`；共享工作区里
   别做变异（会打红别人正在跑的测试）。探针里要**同时**同步实现文件与测试文件——只同步前者
   会让你看到「改坏了居然是绿的」这种假象。
7. **提交**：一个可读的理由一个提交，只 `add` 显式路径；同一文件里别人未提交的 hunk 不要
   混进来（补丁手术的写法见 `dsh-plugin-hub-testing` §10）。
8. **注释与结构一起收口**。结构变了，注释的主语也变了——块内注释跟着块搬走就行，但
   **复述结构的段落注释**（「下面开始做 X」「第一步」）在拆块之后必然说谎，删掉比改准更省。
   同一件事在几处各写一遍的，收口到唯一定义处（`interface.ts` 的承诺、块 `type.ts` 的形状），
   实现处只留「为什么」。**精炼的判据是读者不再被误导，不是注释行数最少**：越写越短的注释
   密度不是目标，边界与取舍的注释（为什么 fail-closed、为什么这里必须留状态码兜底）一句
   都不能少。验收三条：没有复述签名的注释、没有指向已删除符号的注释、没有整段注释掉的旧实现。

## 9. 自检清单

- [ ] 每个域都有 `interface.ts`；没有对上依赖的域**没有** `deps.ts`
- [ ] `impl/` 里没有按值引用本域 `interface.ts`
- [ ] 跨域能力全部经 `deps.ts`，端口都 `Pick` 收窄到位（没有「只用一样却递整个面」）
- [ ] 组合根里没有业务判断，注释与注入方式一致
- [ ] 装配与卸载成对；释放逆序；每个域都复位自己的装配标记
- [ ] 未装配时的行为明确（抛错 / 静默，且理由写在旁边）
- [ ] 宿主端没有 `unknown`、`| null`、`| undefined`、匿名对象类型、闭包工厂
- [ ] 导出面里没有无消费者的符号
- [ ] ABI 名与事件名只有一个物理定义
- [ ] 旧格式的知识全部锁在迁移域；业务域搜不到旧版本的任何词
- [ ] 每个提交都能单独回退；删掉的测试与门禁下限已登记待补
- [ ] 复杂度收尾：先做接缝（把不可达变可达）再抽函数；改前读数在 HEAD 版上用同一规则复现过
- [ ] 抽出来的助手：表达式逐字搬运、模块级私有、没有写入式 `| undefined`/`| null`、导出面零漂移
- [ ] 「行为保持」的每条断言都有 A 级（差分）或 B 级（定向变异）证据，且标级写在交付里
- [ ] 被整模块重写过的面另做过「基线源码级逐条对账」（差分对它们无效，会整片漏掉被删的能力）
- [ ] 注释与结构一起收口：没有复述结构/签名的注释、没有指向已删除符号的注释、没有注释掉的旧实现
- [ ] 注释行数的下降来自删「复述」，不是删「理由」；边界与取舍的注释仍在
- [ ] 探针 worktree 已 `remove --force` + `prune`；提交只含显式路径
