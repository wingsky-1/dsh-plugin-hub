# dsh-plugin-hub-testing — 测试的写法与审法

> 与 `dsh-plugin-hub-dev` 的分工：那个管「怎么改产品代码」，这个管「怎么证明它是对的，
> 以及怎么判断别人写的证明是否成立」。

## 0. 唯一标准

**一条判据只有在「把对应实现改坏就会红」时才算判据。** 其余都只是文字。

这条标准推翻了两种常见做法：为了让覆盖率好看而写的用例，和「读起来很严谨但其实恒真」的
断言。评审时也用同一把尺子——不听作者说这条测的是什么，只看改坏之后它红不红。

## 1. 分层与归属

目录即分类源，机制决定层：`test/unit/**`、`test/integration/**`、`test/client-unit/**`（客户端纯逻辑，
node 环境）、`test/client-dom/**`（要 DOM 的客户端判据，happy-dom，进变异面）、`test/client/**`
（只剩断言产物形态的那部分，**不进**变异面）、`test/e2e/**` 各自的判据、替身面、是否进变异面，
见 DEVELOPMENT.md 的表格。`test/helpers.ts`、`test/client-helpers.ts`、`test/*.worker.mjs`
是支撑模块，**不入任何层、不计 `--min`**。

新增测试文件后的固定动作（漏一步就是「测试存在但门禁没看见」）：

```sh
node scripts/gate/gen-stryker-conf.mjs --sync-test-min   # --min = runner glob 实际文件数
pnpm stryker:gen && pnpm stryker:check                   # 变异面测试清单与拓扑一致
```

## 2. 写之前：这条用例守的是什么

先写下一句话：「把 `X` 改成 `Y`，这条用例必须红。」写不出这句话，说明还没想清守的是什么，
先别写代码。

写完立刻做一次改坏试验（这是本 skill 的核心动作）：

1. 在**探针 worktree** 里改坏那一行（见 §9，不要在正在跑的共享工作区里改）；
2. 跑那条用例 → 期望 `exit 1` 且**只有它红**；
3. 还原 → 期望恢复绿（用 `md5sum` 或 `git diff` 证明真的还原了）。

「改坏了不红」和「一改红一片」都要处理：前者说明判据没落到实现上，后者说明判据不精准
（通常是断言写得太宽或塞了多个事实）。

## 3. 夹具：假件要真、要窄、要露怯

- **端口注入 + 手写假件**是默认做法：被测模块要的外部能力都从构造签名或 `deps.ts` 进，
  测试递一个手写 `class` 假实现，假件里同时记下收到的调用，供断言。
- **禁用**：`vi.mock` / `vi.fn` / `vi.spyOn` / `toBeTruthy` / `toHaveBeenCalled` / `as any` /
  `as never` / `@ts-nocheck`。允许的 `vi` 用法只有：假时钟（`vi.useFakeTimers` /
  `vi.setSystemTime` / `vi.useRealTimers`）与极少数例外（真实 cordis + 假宿主、进程事实、
  `globalThis.fetch`、`node:child_process`）——例外要在文件头写明理由。
- **夹具不许替被测代码做决定**：假件自己实现一遍被测逻辑（例如假仓库自己算 LRU 顺序），
  等于把「实现与实现比」写成了判据。假件只提供原始事实与记录。
- **假件的缺省值不能让判据恒真**：`makeRes()` 之类如果 `headersSent` 写成普通字段，
  「还能不能写头」那条判据就永远成立——用真实 getter。
- **共享夹具进 `test/helpers.ts`**：同一段夹具在两个文件里逐字重复就该合并；但**只服务于
  一个域的夹具不要上提**（共享面越长，改它要读的文件越多）。合并时顺手改名避开近似名
  （`makeRegister` / `makeAgentRegistry` 这种一字之差是陷阱）。

## 4. 时间与并发

- **不用真实 `sleep` 做否定判据**（「等了 100ms 还是没写」在慢盘上必然 flake）。要断「没有
  发生」就用可观测量：待写定时器计数 `vi.getTimerCount()`、磁盘上没有该文件、调用记录为空。
- **不钉时钟做异步等待**：`pollUntil` 的截止时间读真实 `Date.now()`，钉了假钟它永不超时。
  钉钟的用例只用 `await settleMicrotasks()`（排空一轮队列）推进。
- 用假钟就**显式声明 `toFake` 面**（`vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout", "Date"] })`）：
  漏掉 `Date` 会让「多久之后」的判据在假钟与真钟之间漂。文件头写一句本文件的时间纪律。
- **真子进程/真端口的用例**：给足超时、用 `pollUntil` 等可观测信号（文件出现、日志行、端口可连），
  不要等固定时长；这类用例天然慢，放进 `test/e2e/**`。

## 5. 落盘与隔离

- 一切产物进 `mkdtempSync` 出来的目录，`DSH_HOME` 指向它，`afterAll` 里删（仓库内零污染是红线 #218）。
- **时序**：模块级单例（`notifierFile()` 这类）在 `import` 期就把路径定死，所以
  **必须先设 `DSH_HOME` 再动态 `import()`** 被测模块。顺序写反的症状是「单跑绿、连跑红」。
- **fire-and-forget 的落盘会晚于你的清理**：`void writeTextAtomic(...)` 这类异步写在飞的时候，
  `afterAll` 已经把临时目录删了，它落地时会把目录再建回来——实测每跑一次就在 `/tmp` 漏一个。
  「删两次」「排空 20 轮 setImmediate」都挡不住（fs 三连落地更晚）；要确定性收口得让生产面
  提供可 `await` 的落盘句柄，或接受并登记这个已知缺口。
- 钉钟/假端口的用例要**成对收尾**：`afterEach` 里释放单例（`releaseXxx()`），否则残留句柄
  与定时器会串到下一个文件。

## 6. 断言怎么写

- **一次只钉一个事实**。一条用例里混两个事实，红的时候读不出是哪个坏了。
- **精准匹配优先**：能 `toEqual` 就别 `toContain`；能断言完整对象就别只断 `status`；
  不要 `toBeGreaterThan(0)` 这种「有个数就算过」。
- **不要同源期望**：期望值从被测实现里 import 出来（`expect(x).toBe(SOME_CONST)`），等于
  让实现自己判自己——常量改成任何值都绿。要钉就手写一份字面量，让它成为第二份事实源。
- **不要给变异算子的替换文本写断言**：为了杀掉某个字符串变异体去断言 `"Stryker was here"`，
  是把测试绑在工具的实现上。这类存活体应当登记为不可杀（§7）。
- **表驱动 vs 逐条**：同一判断的多个输入档位用 `it.each`；不同行为不要硬塞进一个表，
  那会让失败信息失去指向性。
- **删重复**：同一事实被两个文件各断一遍时，留判据更强的那条；只钉常量的那条如果同时是
  唯一字面量锚（防止有人改常量），保留并注明它是锚而不是行为判据。

## 7. 打不红的时候：等价变异体与判据缺口

把「改坏了不红」当作**信息**而不是失败，逐条分类并写进交付：

| 分类 | 判据 | 处置 |
|---|---|---|
| 等价变异体 | 改动后的语义与原实现完全相同（例：空串时 `slice(0,0)` 是空操作） | 登记：文件:行 + 算子 + **为什么等价**（一到两句可验证的推理） |
| 不可达 | 该行在当前装配/工具布局下走不到（例：源码布局下清单路径算成 `lib/../package.json`） | 登记 + 说明「什么条件下会变可达」 |
| 需改生产写法 | 想杀掉它必须改实现（例：把只落在 `AbortSignal` deadline 上的 clamp 提成纯函数） | 先问「值不值得为可测性改实现」；值得就改并说明，不值得就登记 |

**禁止**为了把数字做上去而写不可证伪的断言（那会把「测试面」变成噪音），也**禁止**为了
让某个变异体红而去断言实现细节（那会把测试绑在重构上）。已知的**判据缺口**要显式写出来
（例：「某初值只在任何 release 之前可见，钉它需要依赖用例文件内顺序，故不钉」）。

## 8. 收口：变异分、CRAP、覆盖率

- 口径：每段阈值与 CRAP 阈值的事实源是 `scripts/data/gauntlet.config.json`；**不要**改它。
  CRAP 在覆盖满时等于圈复杂度，所以「CRAP≤N」等价于「把函数压到 N 以内」。
- 复测命令（走仓库生成的 conf，不要手拼参数）：

  ```sh
  pnpm exec stryker run stryker.conf.d/<pkg>-<段>.json --force --concurrency 4
  ```

  `--force` 绕过增量缓存拿真实全量；**不要**用 `--incremental false`（Stryker 10 会把它当成
  多余位置参数：`too many arguments for 'run'`）。
- **报告会被别的 `pnpm cov` 清空**（`coverage/` 是共享目录）：跑完一段立刻把
  `coverage/mutation/*.json` 快照到草稿目录。CLI 不支持 `--jsonReporter.fileName`，要改落点
  就复制 conf 到 `/tmp` 只改那一行（**仓库 conf 一字不动**——它不是你的门禁）。
- 存活/未覆盖逐条分诊（§7 的三分类 + 「没写用例」），然后才是「这一段达标了吗」。
- 覆盖率与 CRAP 复核：`pnpm cov`（阈值必须 exit 0）、`pnpm crap`（看目标包的超阈项是否清零）。

## 9. 评审别人的测试面

1. **抽验，不采信自述**：从最强的那几条判据开始（e2e、integration、名字承诺最多的），
   逐条改坏一次，看是否只红它。抽验比例按风险定，e2e 与安全相关的必抽。
2. **在探针 worktree 里做**：

   ```sh
   git worktree add --detach /mnt/ssd/worktree/<pkg>-probe HEAD
   ln -sfn <主工作区>/node_modules /mnt/ssd/worktree/<pkg>-probe/node_modules
   # 改坏 → 单跑对应用例 → 记录 exit code 与失败原文 → 还原
   git worktree remove --force /mnt/ssd/worktree/<pkg>-probe && git worktree prune
   ```

   **探针里的测试文件也会过期**：只把实现文件拷进去、忘了拷最新测试文件，会让你看到
   「改坏了居然是绿的」这种假象——两样一起同步。
3. **红绿证据必须贴命令与 exit code**，并且要能看出「只有该用例红」（`Tests 1 failed | N passed`）。
4. **报「一改红一片」**：判据不精准与「跑到了别人的用例」都要指出来。
5. **看删改**：diff 里有没有被删掉的 `expect`（是加强还是弱化）、有没有被放宽的匹配器、
   有没有 `skip`、有没有把断言从严格改成宽松。
6. **看比例**：unit 覆盖白盒分支、integration 覆盖真实组合根、e2e 覆盖真端口真子进程；
   缺层就补层（用兄弟包当先例），而不是把 e2e 的事塞进 unit。

## 10. 提交纪律

- 只 `git add` 显式路径；**同一个文件里别人未提交的 hunk 不要混进你的提交**（要么等对方提交，
  要么用「临时剥离该 hunk → 提交 → 立刻还原」的补丁手术，并在提交信息里写明）。
- 每条命令**贴实际 exit code**；跑不了就写跑不了与原因，不要写「应该没问题」。
- 新增/删除测试文件时**同一批**更新登记（`--min`、`vitest.stryker.d/**`），否则门禁会安静地
  失去下限保护。
- pre-commit 钩子里的 `prettier --write` 会把未格式化的老文件整体重排（实测能把 53 行改动放大
  到 1200 行）。若该文件本就不在格式面内，用 `--no-verify` 提交**并手工跑一遍 lint**，
  在提交信息里写明为什么绕过。全仓格式化是独立工作（#762），不要混进行为修复提交。

## 11. 反面清单（快查）

- [ ] 断言恒真（同源期望、只断「不抛错」、断常量等于它自己、夹具让判据失效）
- [ ] 装饰性断言（改了实现也不红，例如「仍通知」实际走的是另一条分支）
- [ ] 只断 `status`/`ok`，不断随行的关键字段
- [ ] 真实 `sleep` 当否定判据；钉了假钟还用 `pollUntil`
- [ ] `vi.mock/fn/spyOn`、`as any`、`@ts-nocheck`
- [ ] 夹具里重新实现了被测逻辑
- [ ] 重复用例（同一事实两处断言、逐字重复的局部夹具）
- [ ] 为凑覆盖率/变异分写的用例；为杀变异体断言工具替换文本
- [ ] 产物落在仓库里；`DSH_HOME` 没在 `import` 之前设好
- [ ] 删掉的断言没有在交付里说明；存活体没有逐条给理由

## 12. 自检清单

- [ ] 每条新判据都做过「改坏→只它红→还原→绿」，并留下了命令与 exit code
- [ ] 新测试文件已登记层归属、`--min` 与变异面清单已同步
- [ ] 变异分/覆盖率在目标段与阈值上达标；未达标或不可杀项逐条写明性质
- [ ] 夹具是手写的、窄的、不替被测代码做决定的；共享夹具已完成去重
- [ ] 时间与落盘纪律满足（无真实 sleep 否定判据、临时目录、时序正确）
- [ ] 交付里明确区分「实测过的」与「只是读代码判断的」
