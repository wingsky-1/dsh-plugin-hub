AI 时代个人开源方法论
20 天，从 0 到 npm 上的 8 个插件

不是「AI 帮我写了个脚本」的玩具故事，而是一套可以照抄的操作手册：
一个人，业余时间，怎么用 AI 把一个有真实用户的开源项目做到发版 14 次、CI 五条工作流、变异测试全覆盖。

00 心法

先说约束：为什么「一个人 + 无预算」反而是优势

  • 一个人 → 没有沟通损耗，AI 产出的所有上下文都是你的上下文，决策链为零
  • 业余时间 → 逼你把体系做成「异步自治」：你去上班，agent 在跑 issue 队列
  • 无预算 → 依赖成熟开源库是唯一解，正好避开重复造轮子最大的坑
  • 反面真相：约束不是美德，是筛选器——它逼出了 20 天里最重要的三个决策：基建先行、只写胶水、体系自治

本分享的总纲

基建先行（第一天定生死）→ 小步快跑（让门禁追上产能）→ 数据驱动治理（让度量说实话）→ 生态对齐（跟着上游走，别对抗）

共鸣点：很多工程师「想做个自己的项目」但觉得没时间。这页论证的恰是：约束条件催生方法论，时间少反而更需要体系化。

02 Playbook

第一步：第一小时决定整个项目的命运

仓库骨架一次成型monorepo（pnpm workspace）+ 聚合包 + CI + tag 触发发版——这些是「第一天 1 小时」vs「第三周 3 天」的区别
npm 命名当天验证scope 必须匹配 npm 账号名（@wingsky → @wingsky-1 的教训），publishConfig 先配好
让 AI 写「项目宪法」AGENTS.md / 开发规范 / 提交规范——写给 AI 看的文档比写给人看的更重要，因为 AI 是唯一全天候读者
基建即契约构建脚本 TS 化、构建产物契约校验、pack:check 发布物边界——第一周就上，别等「项目大了再说」
金句：个人项目死于「先写功能后补基建」——因为补基建的那天永远不会来。第一天有热情，把最枯燥的事放在热情最高的时候做。
02 Playbook

第二步：让 AI 写得快的秘密——约定先于代码

  • AI 的产出质量 ≈ 你给它的约束质量。本仓的实践：
  • AGENTS.md：全局规则（中文表达、方案先行、红线、worktree 纪律）
  • docs/DEVELOPMENT.md：宿主端/客户端写法、CSS 规范、防 flake 纪律、多端兼容矩阵
  • 规范写成机器可校验的契约——AI 违反文档不会痛，违反 CI 门禁会痛

一个反直觉事实

这个仓 20 天写了 25 个 docs 提交，docs 类 scope 仅次于 notifier。

看起来的「文档项目」，实际是把规范写成了给 AI 执行的接口定义。文档不是给人看的仪式感，是产能的放大器。

给听众的可操作建议：每次 AI 犯同样的错两次，就把这个错写成规范条款或门禁——规范是事故的沉淀物，不是预先的想象力。
02 Playbook

第三步：依赖现代化——不自写是硬纪律

  • 触发：意识到自己在重造轮子后，一次性立项（#8/#47），把自写实现全部替换：
自写实现替换为结果
自写 HTTP/WS 转发http-proxy边界场景（TLS/WS 升级）全部白得
openssl 子进程自签证书selfsigned跨平台、零子进程开销
自写 MCP 协议+传输层@modelcontextprotocol/sdk协议演进跟上游走
自写 MIME 表mime边界类型全覆盖
  • 合规配套：内联 = 分发副本 → 构建链自动归集 license 到 THIRD-PARTY-LICENSES，pack:check 门禁断言
  • AI 时代新特点：AI 「能写出来」不等于「该写」——能写恰恰让重复造轮子的诱惑变大十倍
选型标准顺口说：活跃维护、低依赖、与模块系统/运行平台兼容、不进错端（Node API 库不打进浏览器 bundle）。license 归集是开源发布的合规底线。
02 Playbook

第四步：质量闸门——CI 全绿才可合，没有例外

  • 合并前置五连：build && test && contract && pack:check && typecheck，再加 cov + crap 质量度量
  • 每个功能必须带 smoke 断言（含路由 403/405 围栏、client 契约）——「没测试的功能」在这个仓不存在
  • 覆盖率要看口径：排除 esbuild 内联 vendor，只统计 self-written（#79）；CRAP 卡复杂度×覆盖率热点
  • 变异测试（Stryker）专杀「假测试」：AI 写测试很快，写永不失败的测试更快
  • 成本控制：PR 按路径过滤只跑受影响子包（#85），重型检查放夜间（#433）

给个人项目的忠告

个人项目最容易省略的就是测试。但 AI 协作下反过来：产量越大，越付不起「信任 AI 但不验证」的成本。门禁不是负担，是让你敢点合并的底气。

这页不展开质量细节（那是 v1 的主题），只立「门禁不可省」的论点，给出最简起步版：test + typecheck + build 三连就能挡掉大半事故。
02 Playbook

第五步：AI 工作流——让 agent 自治，让人守闸门

issue 驱动任务只来自 issue；agent 认领 → 独立 worktree → 实现 → PR，主 checkout 永远干净
方案门API/依赖/CI/发版类改动先出方案评论、人工批准再动手——「先讨论再动手」不是美德，是成本控制
授权分级zone/auto 自治 + zone/red-line 人批 + approved 永不代打——权限跟着风险走
独立复核qa 角色按验收判据判收；重要方案拉无上下文的子 agent 做对抗性评审
这是 v2 的浓缩版。个人开发者最需要的两条：worktree 隔离（本地环境稳定压倒一切）和方案门（最贵的错误都是方向性错误）。
02 Playbook

第六步：验证文化——隔离实测 + 证据归档

  • 约定（#51）：界面改动必须隔离环境实测 + 截图归档 docs/archive/ + issue/PR 双向引用
  • 隔离怎么做：临时 DSH_HOME + 独立 profile + 独立端口 + 自动清理——不污染正在使用的环境
  • 后来长出了专用工具（verify-isolated 插件）：一键脚本自动构建/挂载/启动/验证/清理——好约定会自己长出工具
  • AI 的「我改好了」是脑补。证据文化的本质：把「我相信」变成「我看到」

为什么个人项目更需要

没有 QA、没有同事帮你把关。AI 说改好了、CI 是绿的、但你没亲眼看过——这三件事都不等于「能用」。截图归档是最便宜的「亲眼看过」。

听众可以立刻抄的做法：今天就给自己的 UI 项目立一条规矩——改界面的 PR 必须贴运行截图，缺了不合。一周就能感受到效果。

03 踩坑集

踩坑集三：跟上游相处的锚定策略

  • 本项目寄生在上游 dsh 的扩展点上——上游三次发版（alpha.1 / alpha.4 / rc.1）各有破坏性变更
  • 锚定声明：每个插件版本显式声明适配的上游版本，peer 锁版，npm 在不匹配时给出提示
  • 升级前比对：对官方类型层包做编译产物 diff，摸清「导出面不变但行为变了」的暗改（generation 超时策略变化）
  • 绝改宿主源码：只走官方挂载机制——对抗式修改一时爽，上游更新火葬场
  • v0.2.0 顺带退役了 2 个插件（npm 标 deprecated + 发布移除指南）——敢于退役也是生态纪律
适用面广：公司内部做框架/平台的下游团队同理。核心动作三件：锚定声明、升级前产物比对、绝不 fork 修改。
03 踩坑集

发布纪律：把发版变成一个 tag 的事

  • 推 vX.Y.Z tag 触发：管线校验全包版本 == tag → 全量门禁 → publish → GitHub Release
  • 版本号由 tag 唯一驱动，禁止手改 package.json 绕过校验——发版没有人为旁路
  • Release notes 每版入库（中英分节 + 双锚点跳转导航，踩过 GitHub sanitizer 改写锚点的坑）
  • 升级指南随版发布：先升什么后升什么、重启要求、废弃插件移除命令——用户成功 = 你的成功
  • 20 天 14 个版本，唯一一次紧急发版是 SSE 泄漏（v0.1.9）；此后纪律生效，零紧急版
双锚点那个坑值得一句话：GitHub 会把 HTML id 改写成 user-content- 前缀，第三方渲染器又不认——所以每个锚点写两份。小坑，但说明发版文档也要较真。
04 复盘

成本核算：这 20 天到底投入了多少「人时」

~1-2h人日均投入（碎片化：审方案/批红线/复盘）
~95%代码由 agent 产出
40%commits 属质量/流程/文档（非功能）
0转折期之后的紧急发版
  • 结论一：AI 把「写」的成本打到接近零后，人的时间全部转移到了「决定什么是对的」
  • 结论二：40% 非功能投入不是浪费——它换来的是「敢在用户面前保持每天发版」的信心
  • 诚实的代价清单：token 消耗（复核与评审是大头）、体系搭建期的学习成本、偶尔的深夜事故排查
老板视角页。回答「这事值不值」：用 1-2h/天产出一个持续发版的开源插件集——这个投入产出比在 AI 之前的时代不存在。

05 迁移

从个人仓到公司团队：什么能搬，什么要改

直接搬走

· 规范→契约化（门禁代替文档约定）
· 依赖现代化纪律（先调研开源库）
· 证据文化（UI 改动贴实测截图）
· 发布管线（tag 驱动、无人工旁路）
· 防三连：口径单一事实源 / 显式声明 / 变异测试

要改造

· 自治循环：公司场景先从「辅助人」起步（AI 出 PR 人合并），权限逐级放开
· 发版自由度：受公司发布窗口约束，管线对齐内部流程
· 数据边界：内部代码不进外部 agent 平台，先过合规

  • 推荐试点：测试加固 / 依赖升级 / 文档同步——判据清晰、可回滚、验证可自动化
落地路径页，回答「我回去怎么开始」。强调顺序：先搬「直接搬走」列，一个月后复盘，再考虑第二列。
