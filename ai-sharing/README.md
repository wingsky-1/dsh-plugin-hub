# AI 分享草稿 — 三个方向各一版

基于 dsh-plugin-hub 仓库 20 天演进复盘（2026-08-16 ~ 09-04，392 commits / 287 PR / 221 issues / 14 个发版 / 6.1 万行 TS）产出的三个候选分享稿。

> 本目录在仓库之外（分享是公司内部内容，不入公开插件仓）。

## 怎么看

三个 HTML 均为自包含单文件，浏览器双击打开即可放映：

- 翻页：`→` / `←` / 空格 / PgDn / PgUp，`Home` / `End` 跳首尾
- 页脚有页码；底部灰字是每页的讲稿提示（演讲者备注，正式分享前可删）
- 打印 / 导出 PDF：浏览器打印（已做分页适配），即可拿到公司模板里二次加工的素材

## 三版对比

| | v1 质量工程 | v2 协作体系 | v3 个人方法论 |
|---|---|---|---|
| 文件 | `v1-quality-engineering.html` | `v2-agent-teamwork.html` | `v3-personal-oss-playbook.html` |
| 一句话 | AI 把写代码的成本打下来之后，瓶颈转移到了验证 | 把一群 agent 当团队来管理：角色、权限、流程、治理 | 想用 AI 做真东西（不是玩具）的工程师操作手册 |
| 叙事 | 时间线开场 → 质量门禁干货 → 故事佐证 → 方法论收束 | 组织设计视角 → 失败案例 → 治理原则 → 最小落地集 | 步骤化手册 → 踩坑集 → 成本核算 → 迁移到公司的路径 |
| 干货密度 | 最高（CRAP/变异测试/证据文化/防 flake） | 中高（治理设计为主，质量体系作为其中一环） | 中（广度优先，深度可展开） |
| 受众契合 | 质量意识强的研发团队，共鸣面最广 | 正在或准备引入 AI 协作的团队 | 想动手的个人贡献者 |
| 风险 | 通用质量话题，差异化靠真实数据撑 | 对未用 AI 协作的听众代入感弱 | 面面俱到但每点不深 |

## 我的推荐

- 若只能选一个：**v1**（受众最广 + 真实数据支撑 + 「AI 时代质量工程」是当下最有共鸣的命题）
- 若公司正在推 AI 协作落地：选 **v2**，v1 的门禁内容压成其中一节
- v3 更适合写成博客/内网文章，现场分享反而吃亏
