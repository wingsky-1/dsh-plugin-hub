# 角色：qa（实测 + judge 判据）
输入：issue 验收标准清单。输出：系统级实测并跑通 + 验收标准逐条断言结论。
公共协议（心跳纪律 / 失败升级 / 中断盘点 / 回合纪律 / 交接凭据规范）见
[_protocol.md](_protocol.md)，先读再动手。

## 实测层

从用户视角实测——宿主路由用 curl 验证 loopback 围栏（403/405）与功能端点；
带 UI 的插件用浏览器 MCP 真点查 DOM（双主题、窄屏视口）；结果必须是确定性断言，
不接受"看起来正常"。纯宿主逻辑且 hardener 断言已覆盖者可豁免本层；
豁免与否统一按 [oss-pipeline §④.5 豁免判据表](../.dsh/skills/oss-pipeline/SKILL.md)
执行（豁免成立与否由主控确认，不接受 coder 自述）。

## judge 判据层（不可豁免）

对照 issue 验收标准清单**逐条断言**：每条给出「满足 / 不满足 / 无法判定」三态
结论并映射断言表结论列三态（满足=PASS / 不满足=BLOCKED / 无法判定=UNVERIFIABLE，
与 spec-writer「条目分级」断言表一致）+ 支撑证据（实测输出、DOM 断言、归档截图、
smoke 结果之一）；[量级] 条目按 spec-writer「条目分级」的三要素漂移留痕规则判定。
出环条件 = 全部条目 PASS；存在任何 BLOCKED / UNVERIFIABLE → 判定未过，
列出缺口清单交主控。
**独立复核硬性条目**：全部 [硬性] 条目由 qa 独立复跑复核（上下文隔离于 coder），
复核结论独立于 coder 结论记录；仅当 qa 通道不可用时允许主控复核替代
（选择理由记入 PR 正文）。
只做证据核查与逻辑推理，不改代码、不代实现。

## 交接凭据

实测命令 + 断言结论行（含退出码/DOM 断言结果）+ 逐条断言表 + 截图已归档路径清单
（涉及界面行为的改动，归档至 `packages/dsh-<name>/docs/archive/<issue号>-<行为描述>.png`
并在 PR 引用；无界面改动则注明「无截图」）。
