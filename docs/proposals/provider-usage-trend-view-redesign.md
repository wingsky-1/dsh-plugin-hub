## 一、现状与问题清单

现状（trend.ts, 392 行）：三维切换（粒度日/周/月 × 指标 × 适配器）+ 4 张汇总卡 + 手写堆叠柱状 SVG + `<title>` 悬停提示。数据范围写死于 `apply.ts` 的 `TREND_WINDOW = { day: 30, week: 12, month: 12 }`。

### 1.1 数据范围问题

| # | 问题 | 依据 |
|---|---|---|
| R1 | **窗口太短且不可调**：留存默认 180 天（`trendRetentionDays` 可配 1..3650，非硬约束），UI 最多只露 30 天；月视图仅 12 桶且约后 6 桶落在留存外 | `TREND_WINDOW`；`retentionDays ?? 180`；config.ts L98 |
| R2 | **周/月每桶信息密度失衡**：月柱一根 = 30 天用量，与日柱一根 = 1 天同高渲染，月内波动全被抹平 | 系统性问题，非 bug |
| R3 | **首/尾部分桶无标记**：尾桶（今天/本周/本月，进行中）与首桶（留存/起算边缘，周一对齐 + 按天裁剪导致边缘周/月只剩部分天在留存内）都天然偏低，视觉上像「暴跌」 | 现状未区分；周桶按周一对齐 × 留存按天裁的交叉效应 |

### 1.2 表现形态问题

| # | 问题 | 依据 |
|---|---|---|
| F1 | **触屏不可用**：明细只有 `<title>`，iPad / 手机（本插件明确支持移动端）完全无法 hover | trend.ts L147/L150 |
| F2 | **空日无标记**：null 桶不渲染柱，图上不可分辨「无数据」（挂载前 / 超出保留期 / 无会话日）| 数据层 days Map 只在有记录时建桶，token 全 null 与无桶同落 null（见 §3.2 口径声明）|
| F3 | **月视图 X 轴标签丢年份**：`key.slice(5)` 对月键只切出月份号，跨年边界（01/02）不可分辨；窗口 >12 桶后月份号才会重复 | trend.ts L159 |
| F4 | **「峰值桶」卡显示 raw key**（如周首日日期 `2025-12-18`），不翻译成人话 | trend.ts L330 |
| F5 | **图例纯装饰**：不能点选隐藏/聚焦某个 provider 段，段多时堆叠图不可读 | 静态 spans |
| F6 | **切换粒度跳变生硬**：数据重拉期间旧图原样显示，无 loading 态 | fetch 前后无状态差异 |

## 二、备选方案

### 方案 A：保守修补（保持堆叠柱，只修缺陷）

修 F1～F6：触屏点按 tooltip、空桶虚位、月标签带年、峰值卡人话化、图例点选过滤、切换 loading。窗口仍固定。

- 优点：改动最小（纯 client），回归风险低。
- 缺点：R1/R2 不解决——「数据范围和表现形态不好」的主诉求只兑现一半。

### 方案 B：窗口可调 + 双形态视图（推荐）

**窗口**：粒度旁加范围档位，**按粒度 × 实际留存动态生成**（桶数上限 = day→retentionDays、week→⌈retention/7⌉、month→⌈retention/30⌉；`/trend` 响应增补 `retentionDays` 供客户端裁档位）。默认留存 180 天下默认档：日×30、周×13（季度）、月×6（半年）。默认矩阵：日 [7/30/90]、周 [4/13/26]、月 [3/6]；retention 调大后档位自动放宽（如 365 天 → 月 [3/6/12]、日 [7/30/90/180]…按上限裁）。

**形态**：柱/面积双形态 toggle，按粒度给默认（日/周=堆叠柱，月=**堆叠面积**，保留 provider 构成）；两种形态渲染同一份 series。

保留：三维切换、汇总卡（峰值卡人话化）、起算提示。

- 优点：R1/R2/R3 全解；半年粒度月视图成为默认体验；面积图表达「趋势」语义更准。
- 缺点：宿主端 `/trend` 加 `n`/`retentionDays` 输出（小改）；实现量中等。

### 方案 C：日历热力图优先（GitHub 风格）

以「格子颜色深浅 = 当日用量」的年历热力图为主视图（tab：日历 / 柱状），点格子看当天明细。

- 优点：「一年用量分布」心智最直白，天然规避 R2。
- 缺点：色阶表达不了量级差；多 provider 堆叠语义放不进格子；周/月粒度热力图无意义，仍需柱图兜底——等于两套主视图，体量 ≈ B + C 之和。
- 判断：列为**二期可选增强**（日粒度下的第 4 种形态），不作为本次主形态。

**推荐 B**（对抗评审结论：有条件支持，P0 修正已吸收进本版）。以下详设均按 B。

## 三、方案 B 详设（r2，按评审修订）

### 3.1 宿主端（小改）

1. `/trend` 新增 `n` 查询参数：**按粒度 clamp**——day ≤ retentionDays、week ≤ ⌈retentionDays/7⌉、month ≤ ⌈retentionDays/30⌉（上限取自配置的真实 `retentionDays`，非写死 180）；默认仍 30/12/12 兼容现有调用。
2. 响应增补 `retentionDays`（客户端裁档位、标留存边缘的依据）；`firstDay` 已有，继续提供。
3. 顺带纯重构（行为不变，评审 P1-2）：`seriesStacked` 把 `granRange` 提出日循环；`windowSummary` 复用路由已算的 stack 结果，消除单请求双算。n 30→180 放大 6 倍后该点从「毫秒级不致命」变为值得顺手做。

### 3.2 客户端（主要改动，均在 trend.ts）

| 项 | 设计 |
|---|---|
| 范围档位 | 粒度组旁迷你分段器，选项按 `retentionDays` 动态生成（§3.1 矩阵）；切粒度重置为该粒度默认（日30/周13/月6） |
| 部分桶标注（R3） | **本期不加宿主 partial 字段**，客户端按既定契约判定（已核实）：尾桶「进行中」= granKeys 序列最后一项（`lastN*Keys` 恒含当前桶）；首桶「部分」= 桶区间 start 早于 `max(firstDay, 留存下限)` 且有数据。尾桶柱体虚线描边 + tooltip「进行中」角标；首桶 tooltip「部分桶」角标 + 汇总卡「含进行中/部分桶」hint |
| 空桶（F2） | 统一渲染 2px 底部虚位 + tooltip「无数据」。**口径声明**：现有数据模型下「挂载前 / 超保留期 / 无会话日」三者同落 null，不可区分——区分它们需要宿主端桶级信号（如 per-bucket calls），列可选增强，本期不做 |
| 环比口径（P1-1） | 上一窗口区间 start 早于 `firstDay`（prev 窗口不完整）时，环比卡显示「-」并注明「上一窗口数据不完整」，防静默失真与系统性负偏误读 |
| 视图形态 | 柱/面积二选一分段器；默认日/周=柱、月=堆叠面积（保留 provider 构成，byModel 时同理）；**两形态均保持堆叠、不做单色化**（定稿，评审 P1-4）；形态选择**内存态**（会话内记忆，切粒度重置同策略）——不做 localStorage 持久化，与设置页 tab 状态的既有评审决策（#532：宿主 shell 路由事实源不可被插件页假设）保持一致 |
| 堆叠柱升级 | 空桶虚位（上行）；部分桶标注（上行）；月标签 `YY-MM`（修 F3）、周 `MM-DD`、日 `MM-DD`；「进行中」斜纹用 `<defs><pattern>` + 变量色 stroke（不用 color-mix，iOS Safari <16.2 兼容） |
| 堆叠面积 | 复用 charts.ts 既有 niceStep/downsample 思路；**禁用平滑曲线**（Catmull-Rom 过冲会造成负面积视觉失真），null 桶断开为独立连续段；估约 80~120 行（评审修正：原「~60 行」偏低） |
| 触屏 tooltip | 整列命中区（gap 宽）+ pointerdown拾取，明细浮层用绝对定位 div（dou 卡片语言）；键盘遍历降级为可选增强，实现时用单 SVG tabindex + roving，勿每柱 tabindex |
| 图例点选 | 点图例项 toggle 段隐藏（纯前端重渲染）；**Y 域保持全量**（隐藏主导段时与汇总卡比例不脱钩）；隐藏 k≥1 段时卡区显示「已隐藏 k 段」标注（i18n），声明卡为全段口径 |
| 汇总卡 | 峰值人话化：日=`MM-DD`、周=`MM-DD 当周`、月=`YYYY 年 M 月`；Top 卡截断省略 |
| 日粒度上限 | 档位封顶 90（评审 P1-3）：180 桶在 508px 绘图区 gap≈2.8px 糊成一面墙，移动端 viewBox 等比缩放后轴字更小；>90 天的跨度诉求由周/月粒度承担 |

### 3.3 不做（显式出参）

- 不做缩放/平移（≤90 桶 + 抽稀标签足够）；
- 不做下钻明细表（今日按小时细分需 pending 明细行，属二期）；
- 不做空桶三态区分 / 键盘全桶遍历 / localStorage 记忆（分别见 3.2 对应行，均列可选增强或有意不做）；
- **不引入图表库**（调研记录，评审 P1-9）：uPlot 体积最小（≈40KB min）但主题变量/escHtml 转义/堆叠面积均需桥接层，与「发布物内联 + 双主题变量」的集成成本高于收益；Chart.js/ECharts 量级更大且自带 DOM/动画模型与 dou 设计语言不合；本插件 charts.ts 已有 miniAreaSvg 等手写 SVG 先例，延续既有路线。
- 不做日历热力图（方案 C，二期可选）。

### 3.4 兼容与安全

- 主题：全部走 `--dsw-alias-*` 变量（现状已如此）；斜纹 pattern 用变量色 stroke，暗色自动跟随；
- 移动端：tooltip 点按浮层；≤90 桶在 360px 宽度下轴字缩放可接受（现状 30 桶同基线）；DEVELOPMENT.md §6 要求的双主题 + 窄屏（pad/phone）实测纳入验证清单；
- 安全：无新增输入信任面——provider 名等一律 `escHtml`；`n` 参数宿主端按粒度 clamp（纯数字比较，无注入面）；不新增路由与凭据面（README 安全模型无需更新）。

### 3.5 测试

- 纯函数单测：范围默认值矩阵（粒度 × retentionDays 组合）、按粒度 clamp 边界、月标签格式化、首/尾部分桶判定、prev 窗口完整性判定；
- smoke：`/trend?n=` 各粒度 clamp 边界（0/负数/超大/非数字）；响应形状不变式（不破坏现有消费方）；`windowSummary` × 新 n 组合断言（含 prevTotal 落留存外 = null 的行为）；series 长度 == clamp 后 n；
- 控件沿用 #543 哨兵惯例（role=group + aria-pressed，勿用 navigation）；
- i18n：新增键 zh/en 同步（`trendRangeLabel`、`trendRangeDay/Week/Month`（单位后缀）、`trendModeBar/Area`、`trendPartialOngoing`、`trendPartialEdge`、`trendNoData`、`trendPrevIncomplete`、`trendHiddenParts`、`trendViewBar/Area` aria 等 ≈ 10 键）；
- 视觉：`dsh-verify-isolated` 隔离浏览器实测三粒度 × 双主题 × 窄屏（pad/phone）截图归档。
