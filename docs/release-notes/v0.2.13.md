## 中文

本版本把插件集适配到 DSH `0.2.2-rc.5`（Cordis `4.1.0`，需 Node `>=24.9`），5 个包统一发布为
`0.2.13`。官方类型层 catalog（`pnpm-workspace.yaml`）与各包 peerDependencies 已锁步到
`0.2.2-rc.5`；不承诺 alpha、rc.1/rc.2/rc.3 或其他 DSH 版本。聚合包与独立包只能二选一安装，
混装会让 `dsh web` 启动报 duplicate entry 错误。

### 主要变化

- catalog 24 个官方类型层条目与供应链豁免清单同步升到 `0.2.2-rc.5`。框架面未变
  （Cordis `4.1.0`、Schemastery `3.19.0`）；官方本版新增 `dsh-cua-bundle` 与
  `dsh-deepseek-chat-import` 两个包，均由官方自身分发，本插件集不消费、无需配置。
- 宿主服务面 rc.3 → rc.5 无类型面删除（`host-service-diff --check` exit 0）。相对更早的
  rc.1 基线仍有删除项：`agents.isOwnedBy` / `agents.roots`、`subagents` 旧方法组、
  `agentTeams` 与 `deepseekAccount` 的若干方法、`officeToPdf` 服务；本仓消费方对这些删除项
  零引用，从 rc.1 直接跳到 rc.5 的用户只需注意官方自身的行为变化。
- notifier 的子代理归属判定改为读会话 header 的持久化谱系：`origin: subagent` 或
  `delegationDepth > 0`（rc.5 为每个委派子会话持久化该值）。rc.1 / rc.2 的官方
  `agents.isOwnedBy` 探针与后续的 `ctx.subagents` 树关系回退都不再参与；父 agent 消亡后判定
  依然成立，不再因运行时归属缺失把子代理完成报成主任务完成。
- notifier 未装配状态机时在 `settleIdle` 入口当场抛错（
  [#1197](https://github.com/wingsky-1/dsh-plugin-hub/issues/1197)），并补齐 header 三形态
  矩阵回归（[#1201](https://github.com/wingsky-1/dsh-plugin-hub/issues/1201)）：缺装配不会被
  「查不到父」掩盖成一次正常的完成判定。
- mcp-manager 与 provider-usage 只随 catalog 升版，行为与持久化形态不变；两个包的 home
  升级链按此追加空刻度步骤。
- verify-isolated 的目标 runtime 同步钉到 `0.2.2-rc.5`，临时 `DSH_HOME`、独立 profile、
  端口与清理契约不变。

### 从 rc.1 升级的 profile 注意

rc.5 不再发布 `@deepseek-ai/dsh-experimental-agent-team-profile`（该包最后一版是
`0.2.2-rc.1`，agent-team 能力已由 `dsh-base` 内建）。profile 的 `dsh.profile.bundles` 若仍
列着它，需要由使用者本人从
`$DSH_HOME/profiles/<profile>/package.json` 的 `dsh.profile.bundles` 数组里删掉该项；它不在
`dependencies` 里，`dsh plugin remove` 管不到这种 bundle 条目。改完执行
`dsh plugin --profile <profile> install` 重新解析，再启动 `dsh web`。

### 升级

`0.2.13` 发布后执行以下命令。先停止正在运行的 `dsh web`，并备份插件配置与会话数据。

```sh
npm i -g @deepseek-ai/dsh@0.2.2-rc.5
dsh --version

# 全家桶用户（推荐）
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.13
```

独立包用户需对每个已安装成员各执行一次，把最后一条中的包名换成该成员，例如：

```sh
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.13
```

全部更新完成后重启 `dsh web`；其他 profile 将命令中的 `web` 替换成目标 profile。

版本化 home upgrade 链会追加 `0.2.12 → 0.2.13` 无损刻度步骤，持久化形态不变。mcp-manager 的
项目级多 root 配置仍按文件自带 `version` 字段 just-in-time 落定，不进入 home 级步骤表。

## English

This release adapts the plugin collection to DSH `0.2.2-rc.5` (Cordis `4.1.0`, Node `>=24.9`) and
publishes the five maintained packages together as `0.2.13`. The official type-layer catalog in
`pnpm-workspace.yaml` and every package peerDependencies lockstep to `0.2.2-rc.5`; alpha releases,
rc.1/rc.2/rc.3 and other DSH versions remain unsupported. Install either the aggregate or individual
packages, not both; mixing them makes `dsh web` fail at startup with a duplicate entry error.

### Main changes

- The 24 official type-layer catalog entries and the supply-chain exemption list move to
  `0.2.2-rc.5` in lockstep. The framework surface is unchanged (Cordis `4.1.0`, Schemastery
  `3.19.0`). Upstream adds the `dsh-cua-bundle` and `dsh-deepseek-chat-import` packages; the
  official distribution ships both itself, and this plugin collection neither consumes nor
  configures them.
- The host service surface has no typed removals from rc.3 to rc.5 (`host-service-diff --check`
  exits 0). Relative to the older rc.1 baseline some removals remain: `agents.isOwnedBy` and
  `agents.roots`, the old `subagents` method group, several `agentTeams` and `deepseekAccount`
  methods, and the `officeToPdf` service. No consumer in this repository references any of them;
  users jumping straight from rc.1 to rc.5 only need to account for upstream behavior changes.
- notifier classifies subagents by the session header's durable lineage: `origin: subagent` or
  `delegationDepth > 0` (rc.5 persists the depth for every delegated child session). The official
  `agents.isOwnedBy` probe from rc.1/rc.2 and the later `ctx.subagents` tree fallback no longer
  participate. The decision now survives parent disposal, so a subagent completion is no longer
  reported as a main-task completion when runtime ownership is gone.
- notifier throws at the `settleIdle` entry when the state machine is not installed
  ([#1197](https://github.com/wingsky-1/dsh-plugin-hub/issues/1197)) and adds a header
  three-shape matrix regression
  ([#1201](https://github.com/wingsky-1/dsh-plugin-hub/issues/1201)): a missing install can no
  longer hide behind "parent not found" as if it were a normal completion decision.
- mcp-manager and provider-usage only follow the catalog bump; behavior and persisted shape are
  unchanged, and both home upgrade chains append an empty tick step.
- verify-isolated pins its target runtime to `0.2.2-rc.5`; the temporary `DSH_HOME`, dedicated
  profile, port and cleanup contract stay as they were.

### Profile note when upgrading from rc.1

rc.5 no longer publishes `@deepseek-ai/dsh-experimental-agent-team-profile` (its last release is
`0.2.2-rc.1`, and `dsh-base` now provides agent-team itself). If a profile still lists it in
`dsh.profile.bundles`, the user must delete that entry from the `dsh.profile.bundles` array in
`$DSH_HOME/profiles/<profile>/package.json`; it is not a `dependencies` entry, so
`dsh plugin remove` cannot manage it. Then run `dsh plugin --profile <profile> install` to
re-resolve, and start `dsh web` again.

### Upgrade

Run these commands after `0.2.13` is published. First stop the running `dsh web` and back up plugin
configuration and session data.

```sh
npm i -g @deepseek-ai/dsh@0.2.2-rc.5
dsh --version

# aggregate users (recommended)
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.13
```

Individual-package users repeat the last command once for every installed member, replacing the
package name with that member, for example:

```sh
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.13
```

After all updates are complete, restart `dsh web`; for another profile, replace `web` in the
commands with the target profile.

The versioned home upgrade chain appends a lossless `0.2.12 → 0.2.13` step; the persisted shape is
unchanged. mcp-manager project-level multi-root configuration still settles just in time according
to each file's own `version` field and stays outside the home-level step table.
