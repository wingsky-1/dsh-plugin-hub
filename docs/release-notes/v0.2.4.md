# dsh-plugin-hub v0.2.4 Release Notes

> **[中文](#user-content-zh)** · **[English](#user-content-en)**

> **锚定声明：v0.2.4 把适配基线从 `dsh 0.1.2-rc.1` 跃迁到 `dsh 0.1.5-rc.1`**（cordis `4.0.2`）——官方类型层 catalog 与全部插件 peerDependencies 同步升级，并新增 `dsh-client-connection` / `dsh-settings` / `dsh-skill-filesystem` / `dsh-user-questions` 等条目。**本版需要先把 dsh 本体升级到 `0.1.5-rc.1`**：provider-usage 的结算事件、mcp-manager 的目录注入分节顺序、web-file-preview 的官方资源地址都按新宿主契约实现，旧宿主下不保证行为。本插件集**只适配 dsh rc 版本，不对 alpha 版本适配**；安装/更新时若 dsh 版本不匹配，npm/pnpm 会给出 peer 提示。

> **Anchor statement: v0.2.4 moves the supported baseline from `dsh 0.1.2-rc.1` to `dsh 0.1.5-rc.1`** (cordis `4.0.2`) — the official type-layer catalog and every plugin peerDependency move together, adding `dsh-client-connection` / `dsh-settings` / `dsh-skill-filesystem` / `dsh-user-questions`. **Upgrade the dsh CLI to `0.1.5-rc.1` first**: provider-usage settlement events, mcp-manager catalog-injection section ordering and web-file-preview's official resource addressing are all built against the new host contract and are not guaranteed on older hosts. This plugin set only adapts to dsh **rc** releases; **alpha versions are not supported**. npm/pnpm will surface a peer mismatch if your dsh version does not match.

## 中文

### 概述

v0.2.4 是 0.2 线的第四个补丁版本。升级前只有一件事必须先做：**把 dsh 本体升到 `0.1.5-rc.1`**，本版全部插件都按这个版本适配。另外，`dsh-codegraph` 与 `dsh-mem0` 两个包本版起不再发布，装过的请卸载。

功能上，dsh-provider-usage 补齐 cwd / 目录 / 时段三个用量维度，dsh-mcp-manager 增加 MCP 调用统计与 debug 模式，dsh-notifier 增加宿主能力自检面（`/diagnostics`）并把投递终态与理由结构化、声音开关收进渠道条目，dsh-web-file-preview 与 dsh-verify-isolated 分别完成重定位与首启弹窗跳过。工程面继续门禁体系重建与测试基建迁移。


### 关于这次的发版节奏

这一版比预期来得晚，原因是仓库里的技术债比表面看到的更多：门禁与 CI、测试基建、客户端与宿主端的分层都有长期欠账，只能一边梳理一边确认没有行为回退。本版把其中最大的一块做完——**门禁与基建重建**（分层档位、变异判分、覆盖率与产物面收口），以及 **dsh-notifier 宿主端按功能域的大型重构**。因此本版功能新增相对克制，绝大多数改动面向的是「以后改得动、测得准」。

重构还没结束：**0.2.5 会继续这条线**，重点是门禁基建收尾，以及 dsh-mcp-manager、dsh-provider-usage 与客户端半区的结构重构。过程中如果发现行为变化不符合预期，或者有想加的能力，**欢迎随时提 issue 或 PR**。

### 破坏性变更与迁移

**1. 先升级 dsh 本体到 `0.1.5-rc.1`（#695）**

- 本版全部插件的适配基线是 `dsh 0.1.5-rc.1`；**dsh 低于 0.1.5 时不要升级到 0.2.4**，请先升级 dsh 本体；
- 升级命令见「升级指南」。

**2. `dsh-codegraph` 与 `dsh-mem0` 退役（#691）**

- 两个包本版起不再发布（npm 上已标 deprecated，最后一版为 0.2.3），装过的请卸载；
- 退役原因：codegraph 与 CLI 版本强耦合、维护成本高于收益；mem0 的环境隔离等缺陷未收敛。

**3. 升级 dsh 后，部分历史会话可能打不开（#723）**

- 症状：GUI 里报 `cannot safely transform unclassified message source`，该会话始终打不开。原因是 0.2.x 及更早版本落盘的会话产物与 dsh 0.1.5 的会话迁移规则不兼容；
- 处理：**先停掉 dsh web**，再跑一次仓库内的一次性修复脚本（幂等、自动备份、可重复执行），命令见「升级指南」。本版起新产生的会话不再有这个问题。

**4. dsh-notifier 的渠道配置换一种写法（#733）**

- 0.2.3 的 8 个顶层渠道键（`systemEnabled` / `browserEnabled` / `systemNotify` / `browserNotify` / `notifyWhenVisible` / `notifySound` / `browserSound` / `systemSound`）会在升级时被搬进 `channels` 里的两条内置条目，旧键随后删除；升级后再提交这些旧键会返回 400（页面停在升级前时刷新即可）；
- **你的开关状态会被保留**：升级前关过提示音的，升级后仍然静音，不会突然有声。

**5. dsh-web-file-preview 的点击行为变了（#698）**

- `present` 交付物卡片菜单的「用默认应用打开」，以及回复里对 presented 文件的提及点击，从「拉起桌面应用」改为「打开官方右侧栏预览」；
- 原有的自建预览器（Diff / Mermaid / HTML / 二进制下载卡等）不再提供，交给官方预览渲染器；插件不再读取或暴露本机文件，也不再有任何可配置项——不需要就直接卸载。

**6. 给插件开发者：dsh-notifier 对外服务面收敛到 `apiVersion 2`（#733）**

- `wingsky-notify/sent` 事件与 `registerChannel` 退役；`send` 改为返回 `Promise<void>`；
- 只用 `registerKind` 与 `send` 的消费方不受影响；**普通用户对此无感知**。


### 升级指南

**1. dsh 本体**：本版锚定 `dsh 0.1.5-rc.1`，必须升级：

```sh
npm i -g @deepseek-ai/dsh@0.1.5-rc.1
dsh --version   # 应显示 0.1.5-rc.1
```

**2. 升级插件到 0.2.4**（升级后需**重启一次** `dsh web`，bundle 层只在启动时组合）：

```sh
# 全家桶（聚合包 + 其拉齐的子包）升到 0.2.4
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.4

# 或逐个插件指定版本（示例，按需替换包名）
dsh plugin --profile web update @wingsky-1/dsh-notifier@0.2.4
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.4
```

**3. 卸载两个退役包**（若装过）：

```sh
dsh plugin --profile web remove @wingsky-1/dsh-codegraph
dsh plugin --profile web remove @wingsky-1/dsh-mem0
```

**4. 修复升级前落盘的历史会话**（升级 dsh 到 0.1.5 及以后打不开的会话，一次性、可重复执行）：

```sh
# 先停掉 dsh web：正在写入的会话日志不保证可安全重写
# 在仓库根目录执行：
node scripts/maintenance/repair-mcp-catalog-sessions.mjs           # 预演：只列出受影响会话与处数
node scripts/maintenance/repair-mcp-catalog-sessions.mjs --apply   # 落盘，自动生成 .bak-<时间戳> 备份
```

- 默认只读 `<DSH_HOME>`（`--home <dir>` 或 `DSH_HOME` 可覆盖），`--session <id>` 可只处理单个会话；
- 幂等且写后自检（帧结构 + 逐行 JSON + 零遗留旧 kind）；回滚用同名 `.bak-<时间戳>` 覆盖回即可。

> 未全局安装 `dsh` 时，将上述 `dsh plugin ...` 换成 `npx @deepseek-ai/dsh plugin ...` 即可。

## English

### Overview

v0.2.4 is the fourth patch release on the 0.2 line. There is exactly one thing to do first: **upgrade the dsh CLI to `0.1.5-rc.1`**, which every plugin in this release targets. In addition, `dsh-codegraph` and `dsh-mem0` are no longer published from this release on — remove them if you had them installed.

On the feature side, dsh-provider-usage completes cwd / directory / time-of-day usage dimensions, dsh-mcp-manager adds MCP call statistics and a debug mode, dsh-notifier adds a host capability self-check surface (`/diagnostics`) with structured delivery outcomes and per-channel sound, and dsh-web-file-preview and dsh-verify-isolated land their repositioning and first-run dialog skipping respectively. Engineering continues the gate rebuild and the test-infrastructure migration.


### About the Release Cadence

This release is later than expected because the repository carried more technical debt than it appeared to: gates and CI, test tooling, and the client/host layering all had long-standing arrears, and each had to be paid down while confirming that nothing regressed. This version closes the largest block of that work — **the gate and infrastructure rebuild** (tiered gates, mutation scoring, coverage and artifact-surface consolidation) and a **large domain-by-domain rewrite of the dsh-notifier host side**. Feature additions are therefore deliberately modest; most of the change is about being able to change and test things later.

The refactor is not finished: **0.2.5 continues the same line**, focused on closing out the gate infrastructure plus structural refactors of dsh-mcp-manager, dsh-provider-usage and the client half. If something behaves in a way you did not expect, or you want a capability added, **issues and PRs are always welcome**.

### Breaking Changes and Migration

**1. Upgrade the dsh CLI to `0.1.5-rc.1` first (#695)**

- Every plugin in this release targets `dsh 0.1.5-rc.1`; **do not upgrade to 0.2.4 while dsh is below 0.1.5** — upgrade the CLI first;
- Commands are in the Upgrade Guide.

**2. `dsh-codegraph` and `dsh-mem0` are retired (#691)**

- Both packages stop being published from this release (marked deprecated on npm, 0.2.3 is the last version). Remove them if you had them installed;
- Reasons: codegraph is tightly coupled to the codegraph CLI version and costs more to maintain than it returns; mem0 has unresolved environment-isolation defects.

**3. After upgrading dsh, some historical sessions may fail to open (#723)**

- Symptom: the GUI reports `cannot safely transform unclassified message source` and the session never opens. Session artifacts persisted by 0.2.x and earlier are incompatible with dsh 0.1.5's session migration rules;
- Fix: **stop dsh web first**, then run the one-off repair script shipped in the repository (idempotent, backs up automatically, repeatable) — commands are in the Upgrade Guide. Sessions created from this release on are unaffected.

**4. dsh-notifier channel configuration changes shape (#733)**

- The eight top-level channel keys from 0.2.3 (`systemEnabled` / `browserEnabled` / `systemNotify` / `browserNotify` / `notifyWhenVisible` / `notifySound` / `browserSound` / `systemSound`) are folded into the two built-in `channels` entries on upgrade and the old keys deleted; re-submitting those old keys afterwards returns 400 (refresh the page if it was loaded before the upgrade);
- **Your switches are preserved**: if you had notification sound muted, it stays muted — no surprise audio.

**5. dsh-web-file-preview click behaviour changed (#698)**

- The present-artifact card's "open with default app" and inline-code mentions of presented files now open the official right-sidebar preview instead of launching the desktop application;
- The former built-in previewer (Diff / Mermaid / HTML / binary download card and more) is gone, handed to the official preview renderer. The plugin no longer reads or exposes local files and has no configurable options — just uninstall it if you do not need it.

**6. For plugin developers: dsh-notifier's public surface narrows to `apiVersion 2` (#733)**

- The `wingsky-notify/sent` event and `registerChannel` are retired; `send` now returns `Promise<void>`;
- Consumers using only `registerKind` and `send` are unaffected; **regular users will not notice**.


### Upgrade Guide

**1. dsh CLI**: this release targets `dsh 0.1.5-rc.1` and requires an upgrade:

```sh
npm i -g @deepseek-ai/dsh@0.1.5-rc.1
dsh --version   # should print 0.1.5-rc.1
```

**2. Upgrade plugins to 0.2.4** (restart `dsh web` once afterwards — the bundle layer composes only at startup):

```sh
# Bundle (aggregate + the sub-packages it pulls in) to 0.2.4
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.4

# Or pin per-plugin versions (examples — replace with the packages you use)
dsh plugin --profile web update @wingsky-1/dsh-notifier@0.2.4
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.4
```

**3. Remove the two retired packages** (if installed):

```sh
dsh plugin --profile web remove @wingsky-1/dsh-codegraph
dsh plugin --profile web remove @wingsky-1/dsh-mem0
```

**4. Repair historical sessions persisted before the upgrade** (sessions that fail to open after upgrading dsh to 0.1.5+; one-off and repeatable):

```sh
# Stop dsh web first: session logs being written cannot be safely rewritten.
# Run from the repository root:
node scripts/maintenance/repair-mcp-catalog-sessions.mjs           # dry run: list affected sessions and sites
node scripts/maintenance/repair-mcp-catalog-sessions.mjs --apply   # write in place, auto .bak-<timestamp>
```

- Reads `<DSH_HOME>` by default (override with `--home <dir>` or `DSH_HOME`); `--session <id>` limits the run to one session;
- Idempotent with post-write self-checks (frame structure + line-wise JSON + zero leftover old kinds); roll back by copying the matching `.bak-<timestamp>` back over the file.

> If `dsh` is not installed globally, replace `dsh plugin ...` with `npx @deepseek-ai/dsh plugin ...`.
