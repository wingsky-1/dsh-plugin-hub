# v0.2.10

## 中文

本版本将 DSH 适配基线提升到 `0.2.1-rc.2`（Cordis `4.0.5`），包含 MCP 项目根路由修复、notifier 投递与文案修复、provider-usage 并发与凭据读取修复，以及 decision-gateway 与 worktree-sidebar 两个插件的退役。最终合入的修复还让取数失败和陈旧余额更易识别，并加强了发布前的宿主契约检查。安装插件集的新版本前，请先把 DSH 升级到 `0.2.1-rc.2`；不承诺 alpha 适配。

### 兼容范围

- DSH 适配基线：`0.2.1-rc.2`（`pnpm-workspace.yaml` catalog 为版本事实源；各插件包的 peerDependencies 是维护流程生成的精确投影）。
- `@deepseek-ai/cordis` 适配版本：`4.0.5`。
- 本版只适配 DSH `0.2.1-rc.2`；其他 DSH 版本（含 `0.2.0-rc.2`）不在本轮支持范围：旧 DSH 请继续使用 `0.2.9` 已发布版本，需要新版插件时先切换 DSH 本体。

### 兼容性变更（需先升级 DSH）

- catalog 的 `@deepseek-ai/dsh-*` 依赖对齐 `0.2.1-rc.2`，Cordis 升至 `4.0.5`；各插件包的 peerDependencies 按 catalog 精确投影重新生成，安装与 DSH 版本不匹配时 npm/pnpm 会给出 peer 提示。不要用绕过 peer 校验的方式安装。[#1153](https://github.com/wingsky-1/dsh-plugin-hub/pull/1153)
- 聚合包安装契约随基线同步，聚合包含的组件集合与各包 peer 保持一致。[#1153](https://github.com/wingsky-1/dsh-plugin-hub/pull/1153)
- 顺序：先把 DSH 升级到 `0.2.1-rc.2`，再更新插件集（聚合包或单包保持同一版本）。

### 主要变更

- mcp-manager：项目级 MCP 改按调用方 agent 调用开始时的活动 workingDirectory 快照路由，每次调用取一次快照并在本次调用内固定。没有有效活动目录时项目级操作 fail-closed（报「无法确定工作空间」），不回退任何目录猜测值；显式 `@global` 不受项目上下文影响，但需存在已启用的全局来源服务器。项目根发现、并发与连接所有权的实现细节见 [#1151](https://github.com/wingsky-1/dsh-plugin-hub/pull/1151)。
- notifier：修复 Node 20+ 下 webhook 草稿 dry-run 的连接 IP 钉定问题——已核验单一 IP 的请求不再交给 Node 多地址自动选择。DNS/IP 分类与 IP 钉定仍只作用于草稿 dry-run，不适用于保存后的真实投递。[#1148](https://github.com/wingsky-1/dsh-plugin-hub/pull/1148)
- notifier：设置与 README 明确 Bearer 裸 token 不应包含 `Bearer ` 前缀。[#1149](https://github.com/wingsky-1/dsh-plugin-hub/pull/1149)
- notifier：通知产品文案跟随 DSH 显式语言设置（中/英）。普通工具 ID 与 MCP 工具 ID 原样显示，任务名、提问、申请理由、错误原文等调用方内容保持原文；自动语言模式或未支持语言回退中文。无需单独配置通知语言。[#1158](https://github.com/wingsky-1/dsh-plugin-hub/pull/1158)
- provider-usage：修复并发采样互相覆盖的问题——最近运行状态按时间单调合并，已记录的时间不倒退、更新不丢失。[#1154](https://github.com/wingsky-1/dsh-plugin-hub/pull/1154)
- provider-usage：凭据读取迁移到当前 DSH 的 `settings.describe()` 接口；设置服务不可用或读取失败时回落到已知的 DeepSeek 凭据 ref，不再因接口变化静默停止取数。后续修复还保留了凭据服务调用所需的 receiver，避免 `credentials.resolve` 因 receiver 错误抛错以及由此导致的 `/stats` 504；其他超时或故障仍可能返回 504。[#1167](https://github.com/wingsky-1/dsh-plugin-hub/pull/1167)、[#1170](https://github.com/wingsky-1/dsh-plugin-hub/pull/1170)
- provider-usage：取数失败但仍有历史值时，浮动胶囊显示黄点和「最后更新 X 前」；DeepSeek 余额面板在末次采样早于 24 小时时显示具体的最后采样时间。健康信息会记录取数错误，并在成功取数或清理缓存后清除。[#1167](https://github.com/wingsky-1/dsh-plugin-hub/pull/1167)
- verify-isolated：隔离验证脚本去掉必填的 `--dsh` 参数，改为从 PATH 解析 `dsh`，并要求版本精确为 `0.2.1-rc.2`；找不到入口、版本读取失败或版本不符一律 fail-closed，避免产出不属于目标 runtime 的验收证据。[#1160](https://github.com/wingsky-1/dsh-plugin-hub/pull/1160)

### 退役与迁移

- `@wingsky-1/dsh-worktree-sidebar`：已从源码树和 `dsh-plugins-all` 聚合包移除，不再随本版及以后的聚合包分发；已发布的 npm 版本仍可安装。已安装它的用户请阅读[迁移与退役说明](https://github.com/wingsky-1/dsh-plugin-hub/blob/main/docs/migrations/worktree-sidebar.md)。DSH `0.2.1-rc.2` 提供**语义不同**的官方 Git Worktrees 能力（改的是会话活动工作目录，不只是侧栏文件树根），依赖「只看 worktree、不切执行 cwd」语义的工作流需要在迁移前重新验证。退役进度见 [#1141](https://github.com/wingsky-1/dsh-plugin-hub/issues/1141)，迁移说明见 [#1150](https://github.com/wingsky-1/dsh-plugin-hub/pull/1150)，实现见 [#1157](https://github.com/wingsky-1/dsh-plugin-hub/pull/1157)。
- `@wingsky-1/dsh-decision-gateway`：已决定退役，不保留任何兼容版本——无 deprecated 导出、无过渡层、无 tombstone 包，且无直接替代品。归档说明（含残留清理）见[退役归档](https://github.com/wingsky-1/dsh-plugin-hub/blob/main/docs/archive/dsh-decision-gateway-retirement.md)，决策与范围见 [#1147](https://github.com/wingsky-1/dsh-plugin-hub/issues/1147)，实现见 [#1157](https://github.com/wingsky-1/dsh-plugin-hub/pull/1157)。
- `@wingsky-1/dsh-lan-proxy`：**本版不移除该插件**。它计划在本次 `0.2.1-rc.2` 适配之后的下一次上游 rc 适配版本退役，原因是官方上游已覆盖其大部分能力；具体迁移与差异将在届时说明，详见 [#1159](https://github.com/wingsky-1/dsh-plugin-hub/issues/1159)。本版仍随聚合包提供该插件。

### 维护与验证

- 本地 `gate:*` 子步骤会自动移除 `NODE_USE_ENV_PROXY`，避免宿主的代理开关把离线回环测试错误路由到代理。直接运行 notifier 包级测试时，仍应按门禁文档使用 `env -u NODE_USE_ENV_PROXY`。[#1166](https://github.com/wingsky-1/dsh-plugin-hub/pull/1166)
- 宿主契约检查新增官方类型锚、宿主服务方法存在性判据、宿主服务面 diff 和可选的 provider-usage 真实宿主探针，用于更早发现上游接口漂移。[#1169](https://github.com/wingsky-1/dsh-plugin-hub/pull/1169) 这些属于静态契约、类型和门禁工具证据，不代表已在真实宿主通过兼容验收；该 PR 中带凭据的隔离探针通过路径未运行。

### 升级前阅读

1. 先备份 DSH_HOME 下相关插件配置与数据，再把 DSH 升级到 `0.2.1-rc.2`，然后更新插件集（聚合包或单包保持同一版本），重启 `dsh web` 并刷新浏览器页面。安装/更新后 bundle 层只在启动时组合，因此必须重启一次。
2. 若你此前单独安装过 `dsh-worktree-sidebar` 或 `dsh-decision-gateway`：从源码树和聚合包中移除**不会**自动卸载你 profile 里已装好的插件，也不会代你停用它。是否需要卸载由你自行判断，卸载与残留清理方法见上面的迁移说明：

   ```sh
   dsh plugin --profile web remove @wingsky-1/dsh-worktree-sidebar
   dsh plugin --profile web remove @wingsky-1/dsh-decision-gateway
   ```

   来自聚合包安装的 `dsh-worktree-sidebar`：升级到已移除该依赖的本版聚合包即可；仅单独卸载不能让旧聚合包不再加载它。

3. mcp-manager 的项目级 MCP 路由语义本版发生变化：若你的工作流依赖会话创建目录作为路由依据，请在升级后按新的活动目录快照语义核对自己的项目根发现结果（`git` / `.dsh` / `.mcp.json` 标记层）。
4. notifier 的 Bearer token 配置请去掉 `Bearer ` 前缀后再保存。

### 验证边界

已合入的修复均包含离线回归覆盖。`dsh-verify-isolated` 现从 PATH 解析 dsh，只接受 `0.2.1-rc.2`，且不再接受 `--dsh` 参数（[#1160](https://github.com/wingsky-1/dsh-plugin-hub/pull/1160)），可用于目标宿主上的隔离验收。

在 #1166、#1167、#1169、#1170 合入前，已在临时 `DSH_HOME` + 独立 profile 的 DSH `0.2.1-rc.2` 隔离环境中完成一次 5 插件 UI 装载验收：LAN Proxy / MCP Manager / Notifier / Usage Stats / Isolated Verify 全部加载并渲染 UI，无未捕获错误；设置与插件跨重启恢复、卸载后重装（刷新页面）无重复入口。这是此前候选版本的验收证据，未在最终 `origin/main` 上复跑，不能视为已覆盖最新的凭据链、宿主契约和门禁改动。

最终补强中，#1167 另有陈旧胶囊显示的隔离截图；#1170 对真实 DeepSeek 余额接口单独实测了请求成功与 CNY 余额解析，但运行中的 `dsh web` 仍是旧构建，未重启做 UI 验收；#1169 的 provider-usage 真实宿主探针只验证了无凭据 skip 路径，带凭据的通过路径未运行。静态契约、类型检查、包级测试和上述单项实测共同构成本版已有证据，但不等于最终构建的真实宿主兼容验收。

尚未覆盖免刷新 HMR、Session V4 回放、真实会话恢复、notifier SSE/多标签、mcp-manager 连接池与 `ws_mcp_call` 真机、Windows/移动端/LAN HTTPS，因此不宣称完整运行时验收。本版只对上述历史 5 插件隔离 UI 证据及标明的单项实测负责。
另有一项已知限制：notifier 的 SSE `since` 重放缺口（[#1143](https://github.com/wingsky-1/dsh-plugin-hub/issues/1143)）目前仍为 OPEN 且带 `needs-proposal-review`；本版同时合入 notifier 测试补强（[#1152](https://github.com/wingsky-1/dsh-plugin-hub/pull/1152)、[#1156](https://github.com/wingsky-1/dsh-plugin-hub/pull/1156)，均为测试面改动），但不等于该协议缺口已修复。#1143 及 #1117 的剩余事项已移入 v0.2.11 继续跟踪（[#1117](https://github.com/wingsky-1/dsh-plugin-hub/issues/1117)）；#1117 的 lost-update 已修复，并非其所有子问题都延期。

## English

This release raises the DSH compatibility baseline to `0.2.1-rc.2` (Cordis `4.0.5`) and includes MCP project-root routing fixes, notifier delivery and copy fixes, provider-usage concurrency and credential-loading fixes, and the retirement of the decision-gateway and worktree-sidebar plugins. The final merged fixes also make failed fetches and stale balances easier to identify and strengthen pre-release host-contract checks. Upgrade DSH itself to `0.2.1-rc.2` before installing the new plugin versions. Alpha compatibility is not promised.

### Compatibility

- DSH compatibility baseline: `0.2.1-rc.2` (the `pnpm-workspace.yaml` catalog is the source of truth; the peerDependencies of each plugin package are exact projections generated by the maintenance flow).
- Cordis adaptation version: `4.0.5`.
- This release supports only DSH `0.2.1-rc.2`; other DSH versions (including `0.2.0-rc.2`) are out of scope for this round: keep using the published `0.2.9` packages on an older DSH and switch the host first if you need a newer plugin release.

### Compatibility changes (upgrade DSH first)

- The catalog `@deepseek-ai/dsh-*` entries are aligned to `0.2.1-rc.2` and Cordis moves to `4.0.5`; the peerDependencies of each plugin package are regenerated as exact catalog projections, and npm/pnpm reports peer warnings on mismatched DSH versions. Do not bypass peer checks. [#1153](https://github.com/wingsky-1/dsh-plugin-hub/pull/1153)
- The aggregate package installation contract follows the baseline. [#1153](https://github.com/wingsky-1/dsh-plugin-hub/pull/1153)
- Order: upgrade DSH to `0.2.1-rc.2`, then update the plugin set (aggregate or individual packages at the same version).

### Changes

- mcp-manager routes project-level MCP by an active workingDirectory snapshot taken once at call start and fixed for that call. Project-level operations fail closed when no effective active directory exists, without falling back to any directory guess; explicit `@global` is independent of project context but requires an enabled global source server. Project-root discovery, concurrency and connection ownership details are in [#1151](https://github.com/wingsky-1/dsh-plugin-hub/pull/1151).
- notifier fixes webhook draft dry-run connection IP pinning on Node 20+: requests with a single verified IP are no longer handed to Node multi-address selection. DNS/IP classification and IP pinning still apply to draft dry-runs only, not to saved real deliveries. [#1148](https://github.com/wingsky-1/dsh-plugin-hub/pull/1148)
- notifier states explicitly in settings and README that a Bearer token must not include the `Bearer ` prefix. [#1149](https://github.com/wingsky-1/dsh-plugin-hub/pull/1149)
- notifier product copy follows the explicit DSH language setting (Chinese or English). Plain tool IDs and MCP tool IDs are shown as-is, and caller content such as task titles, questions, approval reasons and error text is preserved verbatim; automatic language mode or unsupported languages fall back to Chinese. No separate notification language configuration is needed. [#1158](https://github.com/wingsky-1/dsh-plugin-hub/pull/1158)
- provider-usage fixes concurrent status samples overwriting each other: recent-run state is merged monotonically, so recorded run times never move backwards and no update is lost. [#1154](https://github.com/wingsky-1/dsh-plugin-hub/pull/1154)
- provider-usage now loads credentials through the current DSH `settings.describe()` interface. When the settings service is unavailable or a lookup fails, it falls back to the known DeepSeek credential ref instead of silently ceasing updates after an interface change. A follow-up fix preserves the receiver required by the credential service call, preventing `credentials.resolve` from throwing because of the receiver error and avoiding the resulting `/stats` 504s; other timeouts or failures can still return a 504. [#1167](https://github.com/wingsky-1/dsh-plugin-hub/pull/1167), [#1170](https://github.com/wingsky-1/dsh-plugin-hub/pull/1170)
- provider-usage now shows a yellow dot and "last updated X ago" on the floating pill when a fetch fails but a previous value remains; the DeepSeek balance panel shows the exact last-sample time when the latest sample is older than 24 hours. Health information records fetch errors and clears them after a successful fetch or cache purge. [#1167](https://github.com/wingsky-1/dsh-plugin-hub/pull/1167)
- verify-isolated: the isolated verification script drops the required `--dsh` argument, resolves `dsh` from PATH, and requires the exact version `0.2.1-rc.2`; a missing entry point, an unreadable version or a version mismatch all fail closed, so no acceptance evidence from a different runtime can be produced. [#1160](https://github.com/wingsky-1/dsh-plugin-hub/pull/1160)

### Retirements and migrations

- `@wingsky-1/dsh-worktree-sidebar` is removed from the source tree and the `dsh-plugins-all` aggregate, so it is no longer distributed with this or later aggregate releases; published npm versions remain installable. If you installed it, read the [migration and retirement notes](https://github.com/wingsky-1/dsh-plugin-hub/blob/main/docs/migrations/worktree-sidebar.md). DSH `0.2.1-rc.2` provides official Git Worktrees with **different semantics** (it changes the session working directory, not just the sidebar tree root), so workflows relying on "view the worktree, keep the execution cwd" need re-validation before migrating. Progress is tracked in [#1141](https://github.com/wingsky-1/dsh-plugin-hub/issues/1141), with migration guidance in [#1150](https://github.com/wingsky-1/dsh-plugin-hub/pull/1150) and implementation in [#1157](https://github.com/wingsky-1/dsh-plugin-hub/pull/1157).
- `@wingsky-1/dsh-decision-gateway` is retired with no compatibility kept: no deprecated exports, no shim or transition layer, no tombstone package, and no direct replacement. The archived notes (including leftover cleanup) are in [the retirement archive](https://github.com/wingsky-1/dsh-plugin-hub/blob/main/docs/archive/dsh-decision-gateway-retirement.md); the decision and scope are in [#1147](https://github.com/wingsky-1/dsh-plugin-hub/issues/1147), with implementation in [#1157](https://github.com/wingsky-1/dsh-plugin-hub/pull/1157).
- `@wingsky-1/dsh-lan-proxy`: **this release does not remove the plugin**. It is planned to retire in the next upstream rc adaptation version after this 0.2.1-rc.2 adaptation because upstream now covers most of its capabilities; migration details and differences will be explained then. See [#1159](https://github.com/wingsky-1/dsh-plugin-hub/issues/1159). This release still ships the plugin in the aggregate package.

### Maintenance and verification

- Local `gate:*` child steps now remove `NODE_USE_ENV_PROXY`, so a host proxy switch cannot misroute offline loopback tests through a proxy. Directly running the notifier package tests should still use `env -u NODE_USE_ENV_PROXY` as documented by the gate guide. [#1166](https://github.com/wingsky-1/dsh-plugin-hub/pull/1166)
- Host-contract checks now include official type anchors, a host-service method-existence check, a host-service diff, and an optional real-host provider-usage probe so upstream interface drift is detected earlier. [#1169](https://github.com/wingsky-1/dsh-plugin-hub/pull/1169) These are static-contract, type and gate-tooling evidence, not proof of compatibility acceptance on a real host. The credential-enabled pass path of the isolated probe was not run in that PR.

### Before upgrading

1. Back up the relevant plugin configuration and data under DSH_HOME, upgrade DSH to `0.2.1-rc.2`, then update the plugin set (aggregate or individual packages at the same version), restart `dsh web` and refresh browser pages. A restart is mandatory after install/update because the bundle layer is only assembled at startup.
2. If you installed `dsh-worktree-sidebar` or `dsh-decision-gateway` individually: removing them from the source tree and the aggregate package **does not** automatically uninstall or deactivate the plugins already installed in your profile. Whether to uninstall is your decision; the uninstall commands and leftover cleanup are described above:

   ```sh
   dsh plugin --profile web remove @wingsky-1/dsh-worktree-sidebar
   dsh plugin --profile web remove @wingsky-1/dsh-decision-gateway
   ```

   For `dsh-worktree-sidebar` installed through the aggregate package, updating to this aggregate release (which no longer contains the dependency) is enough; removing the package alone does not stop an older aggregate from loading it.

3. The mcp-manager project-level routing semantics changed in this release. If your workflow relies on the session creation directory for routing, verify your project-root discovery (the `git` / `.dsh` / `.mcp.json` marker layer) against the new active-directory snapshot semantics after upgrading.
4. In notifier, remove the `Bearer ` prefix from Bearer token settings before saving.

### Verification limits

The merged fixes include offline regression coverage. `dsh-verify-isolated` now resolves dsh from PATH, accepts only `0.2.1-rc.2`, and no longer takes the `--dsh` argument ([#1160](https://github.com/wingsky-1/dsh-plugin-hub/pull/1160)), so it can run isolated acceptance on the target host.

Before #1166, #1167, #1169 and #1170 were merged, one isolated five-plugin UI-loading acceptance run was completed against an isolated DSH `0.2.1-rc.2` host (temporary `DSH_HOME` + dedicated profile): LAN Proxy, MCP Manager, Notifier, Usage Stats and Isolated Verify all loaded and rendered their UI with no uncaught errors; settings and plugins survived a restart, and uninstall/reinstall (with a page refresh) produced no duplicate entries. This is evidence for that earlier candidate and was not repeated on the final `origin/main`; it must not be read as covering the latest credential chain, host-contract and gate changes.

Among the final follow-ups, #1167 also has an isolated screenshot for the stale-pill display; #1170 separately exercised the real DeepSeek balance endpoint successfully and parsed a CNY balance, but the running `dsh web` still had the old build and was not restarted for UI acceptance; the provider-usage real-host probe added by #1169 validated only its no-credential skip path, not the credential-enabled pass path. Static contract checks, type checks, package tests and those individual checks are the evidence available for this release, but they are not final-build compatibility acceptance on a real host.

Not yet covered: no-refresh HMR, Session V4 replay, real-session restore, notifier SSE/multi-tab leases, mcp-manager connection pool and `ws_mcp_call` on a real host, and Windows/mobile/LAN HTTPS. This release therefore does not claim full runtime acceptance; it stands behind the earlier isolated five-plugin UI evidence and the explicitly identified follow-up checks only.
One known limitation remains: the notifier SSE `since` replay gap ([#1143](https://github.com/wingsky-1/dsh-plugin-hub/issues/1143)) is still OPEN and labeled `needs-proposal-review`; this release also includes notifier test hardening ([#1152](https://github.com/wingsky-1/dsh-plugin-hub/pull/1152), [#1156](https://github.com/wingsky-1/dsh-plugin-hub/pull/1156)), which does not close that protocol gap. The remaining items from #1143 and #1117 are now tracked in v0.2.11 ([#1117](https://github.com/wingsky-1/dsh-plugin-hub/issues/1117)); the lost-update issue in #1117 has already been fixed, so not all of its sub-issues are deferred.
