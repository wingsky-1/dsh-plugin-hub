## 中文

本版本将插件集适配到 DSH `0.2.2-rc.1`（Cordis `4.1.0`），统一发布 5 个存续包，并退役
`@wingsky-1/dsh-lan-proxy` 插件。native LAN 继续由 DSH 官方入口支持；退役对象仅旧 proxy
插件。升级前请先把 DSH 切换到 `0.2.2-rc.1`，再更新插件集；不承诺 alpha 或混装 peer 的兼容。

### 兼容范围

- DSH 适配基线：`0.2.2-rc.1`；`pnpm-workspace.yaml` catalog 是版本事实源。
- Cordis：`4.1.0`；DSH 运行要求 Node `>=24.9`。
- 5 个存续包统一为 `0.2.11`：`dsh-mcp-manager`、`dsh-notifier`、
  `dsh-provider-usage`、`dsh-verify-isolated` 与 `dsh-plugins-all`。
- 聚合包包含 4 个功能包；独立包与聚合包仍应二选一安装。

### 主要变更

- MCP 复合工具根调用继续由调用者 Agent 的 scoped executor 执行；内部单次转发使用官方公开
  `ToolExecutionPipeline`，保留 opaque parent、agent、toolSet、signal、结果和生命周期。
  内层仅解析外层 admission 后确定的精确私有 dependency，其他名称、失活 parent 或替换注册
  均 fail-closed。
- MCP 图片在真实附件落库前执行每批最多 10 张、每张最多 8 MiB 的硬限制；每个 managed
  client 使用独立 child scope，附件服务晚到、卸载或替换时不会写入旧实例。
- native 非回环短请求通过官方 `requestRejection` 准入，401/403 先于本地 405；非回环 SSE
  绑定 admitted `PeerScope`，释放后先移出广播表再关闭。
- native remote mux 继续协商 `permessage-deflate` 并使用 Ping/不活跃终止；native HTTP
  压缩为 `none | gzip`。
- mcp-manager 还包含新项目根冷启动发现（[#1173](https://github.com/wingsky-1/dsh-plugin-hub/pull/1173)）、
  界面启停状态同步（[#1189](https://github.com/wingsky-1/dsh-plugin-hub/pull/1189)）和会话发布期
  工具限制重入修复（[#1190](https://github.com/wingsky-1/dsh-plugin-hub/pull/1190)）。
- notifier 与 provider-usage 完成 rc.1 生命周期、请求准入和 SSE 适配；notifier 的已退休
  LAN proxy 用户文案已替换为原生 HTTPS、证书信任和系统渠道指引。
- verify-isolated 对接官方 filesystem skill provider，并同步 rc.1 隔离验证 CLI 与脚本契约。
- [#1174](https://github.com/wingsky-1/dsh-plugin-hub/issues/1174) 系列的 lint 与测试形状整理
  降低重复大测试的维护成本，并保持现有判据和阈值。

### LAN proxy 退役与迁移

- `@wingsky-1/dsh-lan-proxy` 已从源码树、聚合包、导出面基线和 CI/mutation 登记中移除
  （[#1159](https://github.com/wingsky-1/dsh-plugin-hub/issues/1159)）；
  已发布 npm 版本仍可显式安装，但不会继续获得 rc 适配。
- native LAN 与旧 proxy 不是等价替换。旧包的逐路径 WebSocket 压缩桥接、半开保活和移动端
  重连策略不承诺等价；旧 settings、配置和证书材料不会被自动删除。
- 部署建议在开放 LAN 前按插件验证认证、HTTP、SSE/WebSocket 与 Host/Origin 反例；涉及
  移动端后台恢复时，再使用真实移动设备复核。它们是部署建议，不构成本补丁的额外发布门禁。
  TLS 成功不能替代调用者认证。迁移细节见
  [LAN proxy 退役迁移](../migrations/dsh-lan-proxy.md)。

### 升级与验证

- 安装顺序：先把 DSH 升级到 `0.2.2-rc.1`，再更新聚合包或独立插件；同一插件只保留一种
  安装方式，更新后重启 `dsh web`。升级前建议备份插件配置与会话数据。
- 有 versioned home upgrade 链的包会追加 `0.2.10 → 0.2.11` 无损刻度步骤；持久化形态没有
  变化时仍保留空步骤。mcp-manager 项目级配置继续按文件版本 JIT 迁移，不进入 home 步骤表。
- MCP 单次结果最多接受 10 张图片，每张最多 8 MiB；超过限制的图片不会继续写入附件存储。
- 8 MiB 附近的大帧 stdio transport 尚未完成端到端验证，当前不能据此推断所有 stdio 或
  streamable-http 环境都接受相同大小的载荷。自然模型多步会话与真实 provider 凭据流程也不在
  本版已覆盖的验证范围内。

## English

This release adapts the plugin collection to DSH `0.2.2-rc.1` (Cordis `4.1.0`), publishes
the five maintained packages together as `0.2.11`, and retires the
`@wingsky-1/dsh-lan-proxy` plugin. Native LAN remains supported by the official DSH entry
point; only the old proxy plugin is retired. Move DSH to `0.2.2-rc.1` before updating the
plugins. Alpha releases and mixed peers remain unsupported.

### Compatibility

- DSH baseline: `0.2.2-rc.1`; the catalog in `pnpm-workspace.yaml` is the version source.
- Cordis: `4.1.0`; DSH requires Node `>=24.9`.
- The five maintained packages share version `0.2.11`: `dsh-mcp-manager`, `dsh-notifier`,
  `dsh-provider-usage`, `dsh-verify-isolated` and `dsh-plugins-all`.
- The aggregate contains the four feature packages. Install either the aggregate or
  individual packages, not both.

### Main changes

- The MCP root call remains on the calling Agent's scoped executor. One internal forward uses
  the official public `ToolExecutionPipeline` while preserving the opaque parent, agent,
  toolSet, signal, result and lifecycle. The inner lookup resolves only the exact private
  dependency established after outer admission; other names, inactive parents, replaced
  registrations and fail-closed cases remain rejected.
- MCP images enforce a hard limit of 10 images per batch and 8 MiB per image before real
  attachment persistence. Each managed client receives an isolated child scope, so late,
  removed and replaced attachment services do not write through stale instances.
- Non-loopback native short requests use official `requestRejection` admission, with 401/403
  before local 405. Non-loopback SSE retains the admitted `PeerScope` and is removed from the
  broadcast table before close.
- Native remote mux continues to negotiate `permessage-deflate` and uses Ping/inactive
  termination. Native HTTP compression is `none | gzip`.
- mcp-manager also includes cold-start project-root discovery
  ([#1173](https://github.com/wingsky-1/dsh-plugin-hub/pull/1173)), UI start/stop state
  synchronization ([#1189](https://github.com/wingsky-1/dsh-plugin-hub/pull/1189)) and
  session-publish tool-restriction reentry fixes
  ([#1190](https://github.com/wingsky-1/dsh-plugin-hub/pull/1190)).
- Notifier and provider-usage complete their rc.1 lifecycle, request-admission and SSE
  adaptation. Retired LAN-proxy guidance in notifier is replaced with native HTTPS,
  certificate-trust and system-channel guidance.
- verify-isolated uses the official filesystem skill provider and follows the rc.1 isolated
  verification CLI and script contract.
- The [#1174](https://github.com/wingsky-1/dsh-plugin-hub/issues/1174) lint and test-shape
  work reduces maintenance cost while preserving existing checks and thresholds.

### LAN proxy retirement and migration

- `@wingsky-1/dsh-lan-proxy` is removed from the source tree, aggregate, export baselines and
  CI/mutation registration
  ([#1159](https://github.com/wingsky-1/dsh-plugin-hub/issues/1159)). Published npm versions
  remain explicitly installable but will not receive rc adaptations.
- Native LAN is not an equivalent replacement. The old package's per-path WebSocket
  compression bridge, half-open keep-alive and mobile reconnection policies are not promised
  as equivalent. Old settings, configuration and certificate material are not deleted.
- Deployment guidance is to verify authentication, HTTP, SSE/WebSocket and Host/Origin
  rejection per plugin before exposing LAN access. When mobile background recovery matters,
  additionally check it on a real mobile device. These are deployment recommendations, not
  additional release gates. Successful TLS does not replace caller authentication. See the
  [LAN proxy migration guide](../migrations/dsh-lan-proxy.en.md).

### Upgrade and validation

- Installation order: upgrade DSH to `0.2.2-rc.1`, then update either the aggregate or the
  individual plugins. Keep one installation form per plugin and restart `dsh web` after the
  update. Back up plugin configuration and session data before upgrading.
- Packages with versioned home upgrade chains receive a lossless `0.2.10 → 0.2.11` step.
  A no-shape-change release still records the empty step. mcp-manager project configuration
  keeps its per-file JIT migration and does not enter the home step table.
- MCP accepts at most 10 images per result and 8 MiB per image. Images above either limit do
  not continue into attachment storage.
- Large-frame stdio transport near the 8 MiB boundary has not completed end-to-end
  verification, so this release does not claim that every stdio or streamable-http
  environment accepts the same payload size. Natural multi-step model sessions and real
  provider-credential flows are also outside the verified scope of this release.
