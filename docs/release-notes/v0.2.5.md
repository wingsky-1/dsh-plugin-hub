## 中文

### 概述

v0.2.5 是 0.2 线的第五个补丁版本：7 个包同版发布（均为 0.2.5），`dsh-web-file-preview` 本版起退役。用户可见的变化共四处：`dsh-worktree-sidebar` 首次随全家桶发布；`dsh-lan-proxy` 新增默认关闭的 host trust 兼容开关；notifier / mcp-manager / lan-proxy 三处结构重构，行为保持兼容；`dsh-provider-usage` 与 `dsh-verify-isolated` 无行为变化。

### 关于这次的发版节奏

本版做完 v0.2.4 预告的三块：mcp-manager 宿主端重构、notifier 客户端分层、lan-proxy 目录重排。没做完的（provider-usage 重构、mcp 后续批次）留给之后版本。遇到行为异常或想要的能力，欢迎提 issue 或 PR。

### 破坏性变更与迁移

**1. `dsh-web-file-preview` 退役（#840）**

- 退役依据：官方 0.1.6 起接管提及点击（`owner.openFile` 改走右侧栏），本包只剩卡片菜单里一个显式外开入口，继续维护的收益已低于成本；npm 上全版本已标 deprecated；
- 装过的请卸载（命令见「升级指南」）；包与全部登记点已从仓库移除（manifest 移入 retired，门禁数据面同步清理）。

**2. `dsh-worktree-sidebar` 首次发布即随全家桶 0.2.5（#847）**

- 这是一个**过渡适配层**：把某个 git worktree 登记给当前会话，使该会话官方右侧栏文件树根指向该 worktree，会话 cwd 不变；官方提供原生 worktree 会话能力之日即退役；
- 首发版本直接拉齐到 0.2.5（开发期 0.1.0 未发布），随 `dsh-plugins-all@0.2.5` 一起装上，无需单独操作；工具面 `ws_worktree_create` / `ws_worktree_register` / `ws_worktree_remove` 只对 git 仓库内的顶层 agent 可见。

**3. lan-proxy 的 host trust 兼容注入默认关闭（#856）**

- 宿主端经官方 `ctx.webServer.tapIndex` 注入自条件脚本：仅当页面尚无 `__DSH_TRANSPORT__` 且自身不在回环 authority 上时才声明 `{ ownsHost: true }`，使局域网页面的设置面恢复 Host 持久化；
- 开关为 lan-proxy 配置中的 `ownsHostCompat`，**默认 `false`**——不打开即与旧版行为一致；配套客户端观测器把过去的静默降级变为可见提示，并同步更新 README 安全模型。

**4. dsh-notifier 从 0.2.4 升级无需任何操作（空步推进刻度）**

- 本版 notifier 的改动全在客户端半区（#769），无服务端存储/配置形态变化；升级链中 0.2.4→0.2.5 一步为空实现，更新后首次启动即自动把刻度推到 0.2.5，历史记录与配置文件逐字不动；
- 给插件开发者：服务端线协议只做加法（围栏拒绝体新增与 `error` 并列的机读 `code` / `status` 字段），旧客户端读不到它们、行为不变。

**5. dsh-mcp-manager 配置文件自动搬家（#767）**

- 升级后首次启动自动搬：`DSH_HOME` 根的 `dsh-mcp.json` 与 `dsh-mcp-user-state.json` 收进 `@wingsky-1/dsh-mcp-manager/`（`mcp.json` / `user-state.json`）；旧文件改名 `.migrated.bak` 留痕，内容逐字不动，无需手动操作；各项目的 `.dsh/mcp.json` 在首次访问时自动收进该项目 `.dsh/@wingsky-1/dsh-mcp-manager/mcp.json`；显式配了 `storePath` 的文件不碰，继续读你指定的文件；客户端一处文案修正：全局归属不再显示 `~/.dsh/dsh-mcp.json` 这个会变的旧路径。

### 升级指南

**1. dsh 本体**：本版基线仍是 `0.1.5-rc.1`，已在 v0.2.4 升过的跳过此步：

```sh
npm i -g @deepseek-ai/dsh@0.1.5-rc.1
dsh --version   # 应显示 0.1.5-rc.1
```

**2. 升级插件到 0.2.5**（升级后需**重启一次** `dsh web`，bundle 层只在启动时组合）：

```sh
# 全家桶（聚合包 + 其拉齐的子包，含首次加入的 sidebar）升到 0.2.5
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.5

# 或逐个插件指定版本（示例，按需替换包名）
dsh plugin --profile web update @wingsky-1/dsh-notifier@0.2.5
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.5
```

**3. 卸载退役包**（若装过）：

```sh
dsh plugin --profile web remove @wingsky-1/dsh-web-file-preview
```

**4. 按需打开 lan-proxy 的 host trust 兼容**（默认关闭；局域网访问设置页需 Host 持久化时再开）：

- 在 lan-proxy 配置中打开 `ownsHostCompat`，随后重启 `dsh web`；客户端会在降级时给出可见提示。

> 未全局安装 `dsh` 时，将上述 `dsh plugin ...` 换成 `npx @deepseek-ai/dsh plugin ...` 即可。

## English

### Overview

v0.2.5 is the fifth patch release on the 0.2 line: seven packages ship together at 0.2.5, and `dsh-web-file-preview` is retired. User-visible changes are fourfold: `dsh-worktree-sidebar` ships with the bundle for the first time; `dsh-lan-proxy` gains a default-off host-trust compatibility switch; three behavior-compatible structural refactors across notifier, mcp-manager and lan-proxy; no behavior change in `dsh-provider-usage` and `dsh-verify-isolated`.

### About the Release Cadence

This release delivers the three blocks announced with v0.2.4: the mcp-manager host-side refactor, notifier client-side layering and lan-proxy directory re-layout. What remains (the provider-usage refactor and later mcp-manager batches) goes to follow-up releases. Unexpected behavior or capability requests are welcome as issues and PRs.

### Breaking Changes and Migration

**1. `dsh-web-file-preview` is retired (#840)**

- Rationale: the official 0.1.6 client takes over mention clicks (`owner.openFile` now routes to the sidebar), leaving a single explicit open entry in the card menu — maintenance cost exceeds return; all versions are marked deprecated on npm;
- Remove it if installed (commands in the Upgrade Guide); the package and all its registrations are gone from the repository (manifest moved to retired, gate data surfaces cleaned up).

**2. `dsh-worktree-sidebar` ships at 0.2.5 with the bundle from day one (#847)**

- This is a **transitional adapter**: it registers a git worktree with the current session so that session's official right-sidebar file tree follows the worktree while the session cwd stays put; it retires once official native worktree sessions land;
- Its first version is aligned straight to 0.2.5 (the 0.1.0 development version was never published) and arrives with `dsh-plugins-all@0.2.5` — nothing extra to do; the `ws_worktree_create` / `ws_worktree_register` / `ws_worktree_remove` tools are visible only to top-level agents inside git repositories.

**3. lan-proxy host-trust compatibility injection defaults to off (#856)**

- The host injects a self-conditional script via the official `ctx.webServer.tapIndex`: only pages that lack `__DSH_TRANSPORT__` and sit on a non-loopback authority declare `{ ownsHost: true }`, restoring Host persistence for the settings surface over LAN;
- The switch is `ownsHostCompat` in the lan-proxy configuration, **default `false`** — leaving it off keeps previous behavior; a client-side observer turns the former silent downgrade into a visible hint, and the README security model is updated accordingly.

**4. Upgrading dsh-notifier from 0.2.4 needs no action (empty step advances the tick)**

- Every notifier change in this release is client-side (#769); there is no server storage/config shape change. The 0.2.4 → 0.2.5 chain step is an empty implementation that advances the stored tick to 0.2.5 automatically on first start, leaving history and configuration byte-identical;
- For plugin developers: the server wire protocol only grows additively (fence refusals gain machine-readable `code` / `status` siblings next to `error`); old clients cannot see them and behave as before.

**5. The dsh-mcp-manager config files move automatically (#767)**

- First start after upgrade moves them: `dsh-mcp.json` and `dsh-mcp-user-state.json` at the `DSH_HOME` root go into `@wingsky-1/dsh-mcp-manager/` (`mcp.json` / `user-state.json`); the old files are kept as `.migrated.bak`, contents byte-identical, nothing to do by hand; each project-level `.dsh/mcp.json` moves into its `.dsh/@wingsky-1/dsh-mcp-manager/mcp.json` on first access; a file with an explicit `storePath` is left alone and keeps being read from the configured path; one client copy fix: the global scope no longer shows the old mutable path `~/.dsh/dsh-mcp.json`.

### Upgrade Guide

**1. dsh CLI**: the baseline is still `0.1.5-rc.1` — skip this step if v0.2.4 already brought you there:

```sh
npm i -g @deepseek-ai/dsh@0.1.5-rc.1
dsh --version   # should print 0.1.5-rc.1
```

**2. Upgrade plugins to 0.2.5** (restart `dsh web` once afterwards — the bundle layer composes only at startup):

```sh
# Bundle (aggregate + the sub-packages it pulls in, sidebar included) to 0.2.5
dsh plugin --profile web update @wingsky-1/dsh-plugins-all@0.2.5

# Or pin per-plugin versions (examples — replace with the packages you use)
dsh plugin --profile web update @wingsky-1/dsh-notifier@0.2.5
dsh plugin --profile web update @wingsky-1/dsh-mcp-manager@0.2.5
```

**3. Remove the retired package** (if installed):

```sh
dsh plugin --profile web remove @wingsky-1/dsh-web-file-preview
```

**4. Optionally enable lan-proxy host-trust compatibility** (off by default; only needed when the settings surface over LAN requires Host persistence):

- Turn on `ownsHostCompat` in the lan-proxy configuration, then restart `dsh web`; the client surfaces a visible hint whenever it degrades.

> If `dsh` is not installed globally, replace `dsh plugin ...` with `npx @deepseek-ai/dsh plugin ...`.
