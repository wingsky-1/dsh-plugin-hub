# dsh-notifier 整改计划（以 #690 为核心）

> 基线：`aa28f99`（#669 PR3 合并后）。本计划由 5 维度独立评审 + 2 轮对抗性评审 + 定稿审查产出，
> 所有存量数字均由协调者独立实测复核。
> 契约口径：**入口 = `<域>/interface.ts`**（本域对外承诺）、**出口 = `<域>/deps.ts`**（本域对上依赖的注入面）。

### 覆盖率修复的有效写法（S1，实测）

| 写法 | 结果 |
|---|---|
| `c8 --import <hook> node <入口>` | **无效**：c8@12 丢弃脚本名之前的参数 → 回到失效口径（`All files 81.27`、状态机 27.24、路由 46.72） |
| `NODE_OPTIONS="--import=<绝对路径>/scripts/test/mutation-lib-to-src-hook.mjs" c8 … node <入口>` | **有效**：**97.05 / 83.68** |
| `c8 … node --import <hook> --test "test/**/*.test.ts"` | **有效**：96.98 / 84.16（不同入口聚合值不同，须在 PR 注明入口） |

约束：hook 路径**必须绝对化**（相对路径在 `pnpm -r` 的子包 cwd 下解析失败）；仓库现无环境变量前缀脚本先例，Windows 兼容性需评估；hook **不得**注入默认 `test` 命令，否则集成面会从产物退回源码，违反测试三层口径。

## 3. 技术路径硬修正（对抗评审与定稿审查实测所得）

| 项 | 原方案的问题 | 实测证据 | 现方案 |
|---|---|---|---|
| 覆盖率修复 | 「给构建脚本开 sourcemap」不可行，且是 6 包共用的仓库级改动 | 开 map 后被两处逻辑删除（构建脚本显式 rm + 游离产物清理的 `.js.map` 分支，其豁免子句为死代码），产物残留悬空 `sourceMappingURL` | 复用既有 lib→src hook，见 §2 有效写法表 |
| 客户端泄漏门禁 | 「防 `node:*` 依赖闭包」打偏，且清单不一致 | `node:*` 已被 browser 平台硬失败；但只含 node **全局**的宿主值（`process.env` / `__dirname`）构建全绿并泄漏进产物。同时合法产物中存在 external 外壳 `__toESM(require("react"))` | **统一为一处清单**：`node:` / `process` / `__dirname` / `Buffer` / `require(`，并**排除 external 外壳**（`require("<bare>")` 形态），加进既有产物契约断言 |
| 路由注入硬失败 | 抓错分支 | 真正的静默点是构建脚本的 `ROUTES` 空分支（零日志），`catch` 不是；改硬失败不误伤任何包（5 个带客户端包的入口均可 import 且导出 ROUTES） | 硬失败加在空分支 |
| seq 归零缺陷 | 引入协议 epoch 过重 | 「回退当前时间戳」无副作用（`?since=` 只做正整数判定、补拉语义不变、老客户端零感知）；客户端 ping 判断先于 seq 判断 | 读文件失败兜底 + ping 帧自愈，共约 9 行 |
| runner 迁移注意点 | 4 处失真/遗漏 | 隔离开关**不能**复现顶层交错故障（同进程仍严格串行）；零匹配 `exit 0`、`exit(0)` 吞失败是两个假绿向量；契约文件改名会打红 wiring 测试；拓扑的 24 条清单**不含**两个既有测试文件，改 glob 后会被纳入变异面 | 判据写死 `tests ≥ 26`；注意点按实测重写；glob 化的变异面扩张需单段干跑评估 |
| 客户端拆分约束 | 「非入口 bare import 会被当 external」依据错误 | 实测被静默内联（产物体积显著放大并触发第三方许可归集） | 约束改为「新增 bare import 会静默放大产物并触发许可归集，须显式评估」（未做构建实验，标注为待验证） |
| `BUILTIN_CHANNELS` 落点 | 「下沉 sdk」会重现值环 | fixture 实测 `pipeline → sdk → pipeline` 判红；下沉中立模块 PASS（值边 3 / 环 0） | 落 `utils/`（公共标识常量，无领域所有者） |

## 4. 决策记录

- **D-1 范围分轨**：A 轨（#690 依赖治理）+ B 轨（架构整改，新 issue）。
- **D-2 R-A 语义**：废除「impl 只 import 本目录 + 本目录 deps.ts」（值侧仅多一跳、耦合零下降），改为「**impl 不得引用他域实现文件**」；新语义下存量接近 0，`deps.ts` 回归其本职——**出口契约与意图声明**。
- **D-3 `src/server/` 半区**：**实施**，但必须排在 S0 门禁粒度修正之后（否则实测会静默废门禁）。
- **D-4 规范演进**：`types/` + `utils/` 目录制写入规范，替代 `docs/DEVELOPMENT.md §2.2` 与 `.dsh/skills/dsh-plugin-hub-dev/SKILL.md` 中的"留 `src/` 根"规则（两处同步）。
- **D-5 共享机制四层**：包内 `types/`/`utils/`、跨包 `shared/`、跨包架构骨架 core 包（候选，另立 tracking issue）、运行时单实例走 cordis 服务面。
- **D-6 落库**：本计划、方法论、core 包提案入库；#690 回填、B 轨 tracking issue、core 包 tracking issue、依赖 issue 清单单独跟踪。

## 7. 交付纪律

- 语言：文档与提交信息使用中文；提交信息遵循约定式提交。
