# dsh-notifier 系统提示音（发声）功能设计

> 适用插件：`@wingsky-1/dsh-notifier`。
> 本文承载**一件事**：宿主的「系统提示音怎么响」——语义、回退链、运行期判据、临时素材、能力面语义与已知边界。
> 决策来源：#785「发声选型定稿 v2」（该 issue 是本系列的决策与台账，随本文落地后关闭，结论沉淀到这里）；落地批次：#782（状态诚实）、#784（能力自检面）、#783（宿主回退链）；**推迟项**：浏览器端语义变更见 #789。
> 本文只写「为什么这么定」与「什么没验过」；具体实现落在 `src/server/channels/impl/system/`，函数级细节不入本文。

---

## 1. 目标与非目标

**目标**：让「宿主到底能不能出声」这件事**诚实**——能响就响，不能响要说清成因并给出下一步，不许静默假装成功。

**非目标**（明确不做，避免以后反复讨论）：

1. 不统一三平台音色语义（见 §2）；
2. 不做浏览器端 `sound: true` 语义变更（推迟，见 §8）；
3. 不做「发行版 → 包名」的**运行期自适应/枚举**映射（只保留内置的**包管理器族级**静态小表，见 §5）；
4. 不枚举 DE / 浏览器 / 发行版组合矩阵；
5. 不引入**带副作用**的能力探测：测不准的维度一律报 `unknown`，不许猜；
6. 不新增任何运行时第三方依赖。

## 2. 三端语义（`sound: true` = 跟随系统默认）

| 端 | 取值 | 为什么 |
| --- | --- | --- |
| **darwin** | 保持现状：`osascript ... sound name` | 改自播是表内等价替换（`ding` 与 `default` 都映射到 Glass），但**不是同一条音频管线**：多起进程、且丢失系统级静音/专注模式约束。听感等价**未实测**（无 mac 主机），故结论保留但理由只以「表同源 + 丢失系统级静音约束」为准 |
| **win32** | 保持现状：toast 自带系统音 | 改自播后 toast 会被置 `silent:true`，改靠 `C:\Windows\Media\*.wav` 的 `existsSync` ⇒ **文件缺失即从「有系统音」退化为彻底无声** |
| **linux 宿主** | **自播**（本文主体） | 桌面守护进程对 sound hint 支持参差（GNOME 默认无声 / KDE 2025 才支持 / Xfce 依赖 libcanberra），不能依赖守护进程 |
| **浏览器** | `sound: true` + 有弹窗 ⇒ 交给 OS；其余 ⇒ 页内自播 | 具体音色（ding/bell/chime/pop）**已经是页内自播**；只有「跟随系统默认 + 有弹窗」这一格仍外包给 OS。推迟改动见 #789 |

## 3. Linux 自播回退链

### 3.1 链序：`paplay → pw-play → aplay → ffplay`

**单一链序，不分档。** 曾考虑「无声音服务时优先 `aplay`/`ffplay`」的分档方案，被否决，理由是**分档判据本身测不准**（本机实测，Ubuntu 22.04 / 2026-09-14）：

- `/run/user/1000/pulse` **存在但为空**；
- 无 `pulseaudio` / `pipewire` 进程；
- 而 D-Bus 会话总线**在**。

⇒ 任何基于目录/总线存在性的探针都会把这台机器**误判成「有声音服务」**，从而把唯一可能出声的 `ffplay` 排到最后。错误分档的失效方向更差（每次投递先起两个必然失败的进程并各等一次超时），故取单一链序。

**如实登记的代价**：只有 `paplay`/`pw-play` 的无头宿主上，链会先白试两个候选。这一格的成因由能力面报 `degraded` 并给出装包建议（§5），用户可见、可处置。

### 3.2 运行期判据：**退出码 + 实测致命标记**（不是「stderr 必须为空」）

**为什么不能用「零输出 = 成功」**（本机实测，ffplay 4.4.2-0ubuntu0.22.04.1）：

- 40 次**成功**播放里 **3 次** stderr 非空，内容是 `ALSA lib pcm.c:8568:(snd_pcm_recover) underrun occurred`（56 B），退出码 0，同期 `/proc/asound/.../status` 为 `RUNNING`；
- 换 `-loglevel quiet` 再跑 30 次，仍有 2 次。

libasound **直接写 stderr**，不受 `-loglevel` 约束。按「零输出」判，真成功会被判失败 ⇒ 链继续 ⇒ **双响**，或声音已经出去而终态报 `failed`。

**判据**：`退出码 ≠ 0` / 被信号杀死 / 超时兜底 / 启动失败 / **命中实测致命标记** ⇒ 失败；其余 ⇒ 成功。stderr 只作 `detail` 记录。

**致命标记表**（7 条，每条都能指到本机样本）：

| 标记 | 触发场景（实测） |
| --- | --- |
| `Failed to open file` | 输入打不开 |
| `audio open failed` | `AUDIODEV=hw:99`（设备不存在），**退出码 0** |
| `Could not initialize SDL` | `SDL_AUDIODRIVER=nonexistent`（该例退出码 1） |
| `Failed to create window or renderer` | 缺 `-nodisp`，**退出码 0** |
| `No such file or directory` | 文件不存在，**退出码 0** |
| `Invalid data found when processing input` | 空文件 / 随机字节，**退出码 0** |
| `Is a directory` | 目录当输入，**退出码 0** |

已知噪声：`ALSA lib ` 开头的行在成功路径上也会出现（3/40），**不在表里**。

**残余 fail-open（如实登记）**：不在表里的失败文本不参与判定。表按行共享给链上每个候选；因为表里全是**失败文本**，命中它只可能把假成功翻成失败，不会误杀成功。

### 3.3 探测

- 走**异步端口**，**禁止 `spawnSync`**（同步探测会挡住第一次投递）；
- 各候选**并行**探测，`players` 收集**全部**命中者，**顺序即优先级**（此前是「首个可用者胜」的单元素数组，两种语义并存是隐患）；
- 探测参数按**表**给且是**数组的数组**，按序试、任一成功即命中：`ffplay --version` 实测 **exit 1**（它只认单横线的 `-version`），只试 `--version` 的实现会把本机唯一可用的 `ffplay` 判成没有。

### 3.4 播放命令行

- `ffplay`：`-hide_banner -loglevel error -nodisp -autoexit <file>`
  - `-nodisp` **必需**：缺它实测退出码 0 但只报 `Failed to create window or renderer: Can't load EGL/GL library...`，根本不出声；
  - `-autoexit` **必需**：缺它进程不退出，只能等超时兜底被杀。
- `paplay` / `pw-play` / `aplay`：`<file>`（**本机无这三个播放器，未实测**，见 §7）。
- 一律**数组传参**，不经 shell。

### 3.5 失败结算与日志

- **首个成功即停**（继续试就是第二声）；
- 全失败才 `failed`，`detail` 带每个候选的成因；`reason.params.bin` = **链上第一个命中候选**（不是表第 0 行——那会报一个本次根本没试过的 bin）；
- 整条链失败时**只留一条** warn；「被信号杀死」多数是我们自己的超时兜底，不刷屏；**超时兜底必须留痕**（旧实现在子进程忽略 SIGTERM 时 `await` 永久挂着、零日志零落盘，本设计改为超时就地按失败结算）。

## 4. 临时音频素材（自包含）

### 4.1 主题文件优先，合成兜底

宿主装了 `sound-theme-freedesktop` 时用其事件音（`/usr/share/sounds/freedesktop/stereo/`，多路径探测）；**候选全缺时**在 Linux 上运行时合成一段 WAV。**darwin / win32 不合成**（它们有系统自带素材与播放路径）。

### 4.2 安全与生命周期

- 目录：`mkdtempSync(join(tmpdir(), "dsh-notifier-"))` —— 本身 0700 + 随机后缀；
- 文件：`{ mode: 0o600, flag: "wx" }`；`wx` 拒已存在路径与符号链接（实测：预置符号链接时报 `EEXIST` 且目标文件未被改写）；
- **只 unlink 本次文件**，目录留到释放面（卸载 / 进程退出）统一删：
  - 实测「spawn 后立即 unlink」播放器报 42 B 的「打不开」；
  - 实测「播放中 unlink」3/3 退出码 0（inode 已打开）；
  - 但**按次删目录**会让并发投递里先完成的那一笔把另一笔正在播的文件一起收走，故目录不按次删。
- `unlink` 必须**晚于最后一次 `onExit`**。
- 声明偏离：文件名用**实例内序号**（`tone-<n>.wav`）而非随机名（#783 §2.4 要求 1 的字面要求）。理由：目录本身随机且 0700，跨 UID 攻击者进不了目录也无从预置，同 UID 已在 README 已披露的残余信任面内。

### 4.3 `/tmp` 不可写

`mkdtemp` 运行期失败是**可上报的失败**，不许静默回落成「没有声音」：

- 只响不弹 / 弹窗也没命令 ⇒ 终态 `skipped` + `reasonSystemToneUnwritable`（`failed` 的定义是「执行过动作而它失败了」，本次没有可执行的动作），宿主原文（`EROFS`/`EACCES`）进 `detail`；
- 弹窗已经出去 ⇒ 终态 `ok` + **一条 warn**（声音是尽力而为）。

## 5. 能力面语义

Linux 的 `sound` 维度是**三态**（此前是「有播放器就 `ok`」，那会把一个已知测不准的事实在能力面上写成 `ok`）：

| 命中情况 | 结论 | 出路 |
| --- | --- | --- |
| 至少一个**非服务型**（`aplay` / `ffplay`） | `ok` | — |
| **只有服务型**（`paplay` / `pw-play`） | `degraded` | `host-only-sound-server-players` |
| 一个都没有 | `unreachable` | `host-no-sound-server-and-player` |
| 音色文件缺失 | **不影响结论**（合成兜底），降为「报告项」留在 `checked` 里 | — |

- `darwin` / `win32` 语义**不变**（只看音色文件）；
- 判据依据来自播放器表的 `needsServer` 字段——**单一事实源**，不为能力面另立名单；表里没有的 bin 一律按「不是非服务型」处理（「不在表里」≠「不需要声音服务」，`ok` 的语义是「至少一个**已知**能直连出声」）；
- 装包建议：`PLAYER_PACKAGES` 三族（`apt` / `dnf` / `pacman`）均为 `["alsa-utils", "ffmpeg"]`（前者提供 `aplay`，后者提供 `ffplay`），`alsa-utils` 在前；**`dnf` 族文案须提示 `ffmpeg` 来自 RPM Fusion**（默认仓库装不上）；认不出包管理器族时**不给包名**（宁可少说一句，不给错的包名）。

## 6. 被否决候选（点名与理由）

| 候选 | 结论 |
| --- | --- |
| `dsh-notify-bell@0.12.0` | **不作否决，登记为必读先例**（MIT）。它已实现同一条链，但**采纳其结论、不采纳其形态**：(1) 它是 `spawnSync` 同步阻塞事件循环，违反本仓「不用 `spawnSync`」的既有纪律；(2) 它的探测判据同为 `--version` + 退出码，与本仓被批评的 `probeCommand` 是同一种弱判据；(3) 它的 BEL 兜底只看退出码，而在 Linux 候选链里**只有 `paplay` 会用退出码自证失败**，照搬其链却不实现其兜底 = 把「播放器在 PATH 里但不出声」从 `failed` 变成 `ok` |
| `node-notifier@10.0.1` | 否决：解包 5.68 MB vendored 二进制（1.97 MB 是 tarball 尺寸，口径更正）；ESM 产物实测 `ReferenceError: __dirname is not defined`；esbuild 不 emit vendor（产物仅 35 KB）⇒ 三平台弹窗后端静默丢失；Linux `sound` 白名单不含该项，对本功能零帮助 |
| `beeep`（Go） | 否决：语言不适用；Linux 走 PC 喇叭 / BEL，而 `dsh web` 的 stdout 是日志文件。可借鉴点：不可达时诚实降级 |
| `wav-encoder@1.3.0` / `wavefile@11.0.0` / `node-wav@0.0.2` / `waveheader@0.0.2` | 否决：四个 WAV 库皆停更 6–10 年 ⇒ 自研 RIFF 头 + 正弦采样 |
| 分档链（无头优先） | 否决：见 §3.1 |
| 「零输出 = 成功」判据 | 否决：见 §3.2 |
| 同步探测（`spawnSync`） | 否决：违反既有异步端口纪律 |

## 7. 已知边界与未实测面

**未实测**（本机不存在，`command -v` 逐条 exit 1）：

- `aplay` / `paplay` / `pw-play` / `notify-send` 的**探测参数、失败文本、退出码全部未实测**；
- 因此代码与标记表里**一条未实测字符串都没有**（表里 7 条全可指到 ffplay 样本）；
- 同理，这三个播放器的 argv 在测试里只按「表导出」断言，不写死字面量——代价是变异切片里 5 个结构型变异体存活（这是**不为变异分补装饰性断言**的有意取舍）。

**不可判定**：

- `SDL_AUDIODRIVER=dummy` 配 `AUDIODEV=null` 时退出码 0、stderr 0 B，但 ALSA 设备始终 `closed` ⇒ 该配置**不能**作为「出声成功」的证据，只可作对照。

**残余风险**：

- 判据 fail-open（不在标记表里的失败文本不参与判定）；
- 能力面**无法**反映 `/tmp` 只读（探针必须无副作用），只能在投递期上报；
- 成功路径**无法**暴露「本次用了哪个候选、是否已耗尽」（要满足需扩 `DeliverResult.ok` 的形状）。

## 8. 推迟项：浏览器端

浏览器端 `sound: true` 的语义变更**整批推迟**，独立跟踪于 **#789**（已排入 `v0.2.5` 里程碑）。当前行为已在设置页文案中如实标注：`chSoundFollowHint` = 「浏览器卡：交给操作系统发声（不 silent）」。

推迟不影响本设计在宿主端的目标：用户能看到「宿主放不出声」并按 `remediation` 处置。
