# Agent Note: Catalog 目录名转义修复

Status: implemented

## Problem

能力目录把服务器名直接拼入 system-reminder 正文，而服务器名与描述同为远端可控输入。只有描述经过转义，名字中的标签字符保留原样进入提示面，标签逃逸改写注入语义；回读侧若不同步解转义，注入比对恒不等，每轮误发修正帧。

## Decision

渲染对名与描述采用同一转义口径，解析侧对名做对称解转义，使回读条目与组装条目逐字一致；摘要口径保持只含原始名，转义属于展现层手段，不进入去重依据。

## Alternatives considered

- 加载侧拒载含特殊字符的服务器名：丢弃整台服务器的能力陈述，目录与实际可调集合脱节，且条目数抖动破坏摘要稳定；转义保留完整信息，代价更小，故不采用。
- 维持仅转义描述的现状：在名字上不断言转义：放行真实存在的注入向量，测试无法约束风险点；补齐名字断言的成本仅为对称的两处改动，故不维持现状。

## Consequences

目录正文不再信任任何远端字符串，新增用例同时约束渲染与解析两侧，任一侧回退都会变红；代价是名字往返多一次编解码，且反引号仍不在转义范围内，含反引号的名字沿用原有解析限制。
