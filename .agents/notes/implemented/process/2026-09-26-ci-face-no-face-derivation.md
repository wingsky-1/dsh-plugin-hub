# Agent Note: CI 归属面登记的「无面豁免」改为推导

Status: implemented

## Problem

`scripts/data/ci-face-registry.json` 登记 `packages/` 之外每个 tracked 文件的 CI 归属面。它过去允许一种写法：`"faces": []` 加一句人工 `why`，表示「这个文件已登记，但声明它不需要任何 CI 面」。

这个写法把结论变成了声明。任何人新增一个文件，只要补一行 `faces: []` 就能让它静默退出所有切片，而当时全部断言一条都不会红——面覆盖判据的循环体是 `for (const face of e.faces)`，空数组不进循环，没有主张就没有可核对项。更糟的是 `why` 会被要求填写，读起来却像在陈述一个既有事实，看不出它是当年的一次选择。

维护者在 #875 的裁决把这件事定性了：结构性不适用不是豁免，真不适用时规则应按对象特征自动识别，不靠登记。原话已经写在仓库里，缺的是执行。

## Decision

`faces` 改为可缺省字段，三条规则同时成立才算「不需要面」，由 [`test/ci-face-coverage.test.ts`](../../../../scripts/test/ci-face-coverage.test.ts) 逐文件重算：

- **N1 无切片触发**：`ci.yml` 任何面的 glob 都不命中该文件。paths-filter 只在命中时才点亮面，所以「不被任何 glob 命中」就是「改它不会触发任何切片」这一事实的机器形态。
- **N2 无包消费**：没有任何 `packages/**` 下的代码文件按真实 import 图 import/require 它。按解析后的路径比对而非字面包含，README 里提到文件名不算数。
- **N3 消费者非包内**：覆盖该文件的条目的 `consumers` 不含 `packages/**` 路径，即消费它的入口都是仓级常驻闸。

写 `faces: []` 判红——空数组这条通道已经物理删除；不需要面就把字段整个删掉。`why` 只在条目声明了面时必填：无面条目的理由是推导出来的，再手写一遍就是把推导出的事实退化成登记的声明。

面归属同时改为**逐文件集合等值**：命中某文件的所有条目声明的面之并集，必须恰好等于 `ci.yml` 为该文件派生出的面集合。**这是把旧的两条判据合成一条并让语义显式，不是收紧**——「面覆盖」给 `registered ⊆ derived`、「反向核对」给 `derived ⊆ registered`，两条合起来本就蕴含等值；`origin/main` 上同一夹具照样判红。

## 26 条无面条目：推导事实与显式决策

26 条里绝大多数的原 `why` 只是描述「消费方是哪个常驻闸」，这部分由 N1/N2/N3 覆盖，不再复述。下列几条的原 `why` 里含有**今天仍然成立的选择或描述**（其中 `ci-face-registry.json`、`gate-wiring-exceptions.json`、`scripts/test/**` 三行是描述或复述，`.agents/**` 一行是被本轮撤回的措辞，其余四行才是真正的选择），删掉会让后人把推导结果误读成「碰巧如此」然后去「修正」它，故在此留档：

| path | 当年的决策与描述 | 出处 |
| --- | --- | --- |
| `docs/**` | **刻意**不在全局面。这个「刻意」是 #220 的决策，不是推导的副产品；将来推导规则变化时，不得据此把它改回全局面 | #220 |
| `agents/**` | 从全局面移出，与 `docs/**` 同等待遇 | #899 |
| `scripts/data/threshold-registry.json` | 声明表归 global 要改 `ci.yml` 的 filters，那是红线段、收益为零，故不归 | #843 D5 |
| `scripts/data/vendored-binaries.json` | 同一判断的复述：只声明哪些副本已登记许可，不改 filters | 批 2b |
| `scripts/data/ci-face-registry.json` | 本表只声明并核对归属，不改任何 filters | #742 |
| `scripts/data/gate-wiring-exceptions.json` | 同上，接线例外台账同理 | #843 |
| `scripts/test/**` | 除 `run-vitest.mjs` 外只服务 `test:scripts`；该文件由自己的专属条目主张 `global` | #742 阶段 2.1 |
| `.agents/**` | 原 `why` 写「faces 空数组为显式豁免（无需包面）」——**这句措辞本轮被推翻**。留痕的理由是：措辞被推翻而无人记录，正是登记表语义漂移的典型形态——文件在、字还在，但意思已经反了 | 本轮 |

另有一条不是面归属决策而是已知缺口：`scripts/derive/host-contract.mjs` 的 `consumerGap.kind=none`，trackingIssue **#802**，接线后要把 `consumers` 补上。

## 新增文件如何判面

新增或改名一个 `packages/` 之外的文件时，判定依据是 **N1/N2/N3 的重算结果，不是任何人的 `why`**。具体地：

1. 先确认它被某条登记条目覆盖——未登记即红，这是完整性断言。
2. 若 `ci.yml` 有 glob 命中它（N1 不成立），它需要面：补上真实的面名，且声明的面并集要与派生面集合**完全相等**。
3. 若 `ci.yml` 无 glob 命中它，它**候选**无面，还要过 N2 与 N3：有没有 `packages/**` 代码真的 import 它；覆盖它的条目的 `consumers` 里有没有包内路径。两条都过才是无面。
4. 无面**不要**再补 `faces: []`，也不需要补 `why`。

换句话说，登记表里不再有任何一句话能单独决定一个文件的面归属。这是有意的。

## Alternatives considered

- **删掉这 26 条，让无面文件完全不进登记表，由一条派生规则整体覆盖**：最彻底，但会连带删掉它们的 `consumers` / `consumerGap`。#843 L5 的载体自证断言要求「consumers 条目 + consumerGap 条目 = 全部 entries」，删条目会把引用核对的覆盖面从 73 条缩到 47 条，等于用「更干净」换掉一条既有断言的强度，不接受。
- **保留 `faces: []`，只把它绑到 N2 上**：改动最小，但通道还在——补一行 `faces: []` 加一句 `why` 仍然是合法的登记动作，而「登记」这个动作本身就是裁决要消除的东西。
- **为无面文件往 `ci.yml` 加 global glob，让它们名正言顺**：要改 `.github/**`，是红线段；而且 `docs/**`、`*.md` 这类进了 global 会让改一行文档触发全量切片，代价与收益完全不成比例。
- **按条目求值（每个缺省 `faces` 的条目断言「我覆盖的文件都无面」）**：见 Consequences，这是本篇最值得记住的一条，它已被否。

## Consequences

- **收益一：结论不可被随手写下。** 无面资格要同时过三条规则，其中 N2 依赖真实 import 图。新增文件若真是某个包的构建/测试输入，登记成无面会当场判红——旧口径对此完全无感。
- **收益二（措辞更正，务必看清）：面归属的两条断言合并为一条显式等值判据——这是可读性与显式性的改进，强度与 `origin/main` 持平。** 我最初把本轮写成「子集判据 → 集合等值 = 收紧」，**那是错的**：`origin/main` 的「面覆盖」给 `registered ⊆ derived`、「反向核对」给 `derived ⊆ registered`，两条合起来已经蕴含等值。复核在同一夹具上实测 `origin/main` 同样判红：多声明一个面 exit 1、漏一个面 exit 1、把有面条目退回 `faces: []` 也 exit 1。合成之后的好处是读者不必自己把两条推到一起，判词直接指出是哪个文件、并集与派生各是什么。
- **收益三：沿革与推导分了家。** 推导结论进判据（`$comment` 与本文），决策记录进本文。gate 输入与决策记录不再是同一个字段。
- **代价一：glob 登记有条目级与文件级两种求值，同一份数据上给出相反结论。** 本篇第一版实现按条目求值，把 `scripts/test/**` 读成「我覆盖的文件都无面」，于是对它命中的 `scripts/test/run-vitest.mjs` 报了假阳性——那个文件确实在 global 面里，但它的面由专属条目 `scripts/test/run-vitest.mjs` 主张，属于并集语义下的正常分工，不是缺陷。改成按文件求值（先判 N1，有面就跳过）才对。这条是这类登记表判据的通病：登记项是 glob，判定对象却是文件；求值粒度选错，结论就翻转。后来人做类似改造请先想清楚求值对象是谁。
- **代价二：口径不再登记在文件里，每次靠规则重算。** 新增文件会被新规则自动扫到——这是不靠人同步的代价，也是收益：合入主干后新进来的文件仍要逐个过 N1/N2/N3。本篇成文时主干刚合入三个新文件（`scripts/maintenance/equiv-check.ts`、`scripts/test/build-script-shape.test.ts`、`scripts/test/equiv-check.test.ts`），universe 从 530 涨到 533、无面文件从 290 涨到 293，三者都经实测逐条通过。换句话说，新增文件比登记在册的文件多一次验证面。
- **代价三：`why` 的适用范围按「有无面」一分为二**——声明了面就仍然必须写（#742 既有断言，本次改造未松开它；首版实现漏掉了这个分支、把断言净松开了，是复核抓出来的），无面条目则不得写。登记表里 `why` 只承载「为什么归这个面」，历史语境不再逐条留在原处，只在本文集中留档。将来要回溯某条当初为什么这么判，来本文而不是去登记表找。
- **口径澄清：这不是在修一个存量漏洞。** `scripts/test/**` 声明 `faces: []` 而其命中的 `run-vitest.mjs` 在 global 面里，这个组合在旧模型下是自洽的——空数组即「不主张面」，面由专属条目主张，并集完整。对 origin/main 全量 533 个 universe 文件实测「并集声明面 vs 派生面」不等者 0 个、「派生有面但无人主张」者 0 个；反证把 `scripts/test/**` 的 `faces` 改成 `["dsh-notifier"]` 旧模型判红，说明旧判据对写错的面咬得住。改造前后判定结果完全一致，变的只是理由来源。
- **N2 的已知漏报面（逐类实测，别把它当编译器语义用）**：说明符提取是文本级正则加路径规范化，以下八类读不出来——1 动态拼接 specifier（``import(`./${n}.ts`)``）、2 模板字面量 import、3 相对路径带 `#fragment`、4 `?query` 后缀、5 `createRequire` 产出的 `req(...)`、6 `import.meta.resolve`、7 `readFileSync(new URL(...))` 这类运行时读文件（根本不是 import 面）、8 `.js` 说明符指向磁盘上真实存在的 `.ts`。**能检出的、不要误列为漏报**：静态 `from` 字面量、`import("字面量")`（含 `if (x) import(...)` 这类编译期条件导入）、`require("字面量")`、无 from 的副作用导入 `import "x"`——我最初把「编译期条件导入」写成漏报，那是反的，实测能检出。
- **N2/N3 的真实防护从未被端到端验证过。** 在当前真实数据上，N2 与 N3 的检出**恒为 0/293**——293 个无面文件没有一个被它们判负。它们今天的价值完全靠载体自证 3/4/5（import 扫描面非空、两个正例样本仍被解析、N3 有反例条目）维持。判据真实拦下 N2 的唯一一次记录是注入实验：让 `dsh-notifier` 真的 `import` 一个无面文件，判红。后人若要依赖 N2 判红，先自己造一个真消费点，不要假定它已经在生产数据上生效过。
- **N1 在真实树上是死分支。** 判定循环先按「`derivedFaces(file).length > 0` 就跳过」把 N1 施加了一遍，因此传给判定本体的 `derived` 对被处理文件恒为空数组，`judgeNoFace` 内的 N1 分支在真实数据上不可达。保留它的意义是语义完整（判定本体自洽，不依赖调用方的守卫顺序）与载体自证可触达（合成反样本 `judgeNoFace({derived:["global"],...})` 能打到这一支）。复核已确认：N2/N3 不是装饰——同时去掉循环守卫与判定本体的 N1 后，N3 能在真实数据上报红。
