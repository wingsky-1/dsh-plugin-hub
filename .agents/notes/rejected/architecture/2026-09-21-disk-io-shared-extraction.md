# Agent Note: 落盘 IO 统一抽取被否

Status: rejected — 错误模型、队列位置与文件模式三向分叉，统一抽取省不掉分支，只会搬运复杂度，故各包自持

## Problem

三处落盘面形状相似（同目录临时文件加 rename 原子覆盖），但语义各不相同：通知包 server 下共享层 file-io（同步读加异步与同步双写面），侧边栏包 server 下共享层 file-io（同步读加异步写面），用量包 schedule 域 store（按根串行的 last-run 读写）。有人提议把三者抽成一处跨包共享落盘 helper，调用方只传路径与文本。

## Proposal

新增一处跨包共享落盘实现，统一提供读全文与原子写全文，含临时名生成、父目录补齐、错误表达，三包删除各自实现并改为调用它。

## Alternatives considered

### 统一抽取（被否）

对方最强的理由：三处核心都是写临时文件再 rename，同目录 rename 原子语义同一套，收成一处后并发双写共用临时名之类的修补只改一次，少三份重复代码，看起来是稳赚的复用。

否决：形状相同不等于语义相同，统一后分支一个省不掉。

- 错误模型三裂：通知与侧边栏侧以返回值表达失败（FileWrite 与 FileRead，失败带原因文本，调用方处置是保持上次成功态加出声，类型上不抛）；用量侧以抛异常表达失败（写面返回空，失败直接抛，调用链按失败显式处理）。统一签名只能二选一，选返回值则用量侧调用方要重写失败分支，选抛异常则前两者类型契约被击穿。
- 队列位置三异：通知状态面是内存镜像加 debounce 窗口合并写，侧边栏绑定面是直写（读时纯逻辑解析兜底），用量 last-run 面是按根承诺链串行加写前重读全量快照。队列与合并逻辑归属各域（按根、按文件、按时间窗），抽走落盘原语带不走队列，留下的三套队列仍各写各的，共享层只剩下一层薄转发。
- 文件模式三岔：用量 last-run 写带受限文件模式与结构字段（模式位与版本与更新时间一起落盘），通知与侧边栏侧是普通文本写无模式位；同步与异步切分也不同（通知侧装配路径要同步写，侧边栏侧无同步写面，用量侧只有异步）。统一函数要为模式位、同步异步、附加字段各开开关，调用点比分叉前更啰嗦。

### 各包自持、只修临时名（被采纳）

三处各自保留实现，修补只收敛形状不收敛语义：两处共享层 file-io 的临时名统一为唯一临时名（进程号加时间戳加随机后缀，同进程并发双写不再共用同一临时文件，rename 先后顺序仍无保证但内容各自完整）；不做临时文件清理的口径保持不动。用量侧 per-root 链与重读逻辑留在 schedule 域内。

## Consequences

- 收益：调用方错误分支零改动（返回值侧继续判返回值，抛异常侧继续接异常）；队列归属留在最懂业务的域里（防丢更新的串行与合并逻辑不搬家）；新增落盘需求按消费者集合先判档，不空降跨包。
- 代价：三份临时名生成与补目录逻辑字面重复；以后改原子写语义要改三处，靠评审保证同形。重复的是十行级形状，统一省掉的是形状、留下的是三套语义分支，前者靠评审便宜，后者进共享层则变贵。
