# Agent Note: placement-math 共享抽取被否

Status: rejected — 包级常量与公开命名已分叉，构建期各自内联本就零运行时共享，故两包自持并以评审保证同构

## Problem

两包各持一份浮窗定位与层级与断点纯函数：连接管理包内 src 下 shared 目录 placement-math，统计用量包内 src 下 shared 目录 placement-math。两者函数体同构，仓库根 shared 下的旧 placement-math 实现已退役。有人提议把其中一份升为跨包共享，另一包经相对路径引用，消灭字面重复。

## Proposal

在仓库根 shared 下恢复一处 placement-math 共享实现，两包删除各自副本并改为引用它，公开导出面保持不变。

## Alternatives considered

### 升为跨包共享（被否）

对方最强的理由：两份实现逐行同构是肉眼可见的重复，单源之后改算法只改一处，不会漏同步另一处；跨包共享目录本来就是为这种纯函数准备的，扇入两包正好达标。

否决：同构的是函数体，分叉的是包级事实，抽上去分支藏不住。

- 包级常量分叉：默认层级基准两包各钉死自家样式事实（一包对应层级十，一包对应层级四十），值域下界上界与面板派生量虽同形，默认值不同。共享实现要么把默认值参数化（公开签名变化），要么保留两处包级常量转发（重复一字不少）。
- 公开命名分叉：垂直锚点规则一包公开名为 panelAnchorForPosition，一包公开名为 panelAnchorForPlacement，语义同为底部锚点向上弹出、其余向下弹出。共享只能二选一改名，另一包的公开导出面即 breaking，或在门面层各包别名转出（又是一层转发）。
- 构建期独立副本零收益：两包 shared 目录经门面转出的目标由构建链各自内联进自家浏览器产物，跨包相对引用同样在构建期内联，结果仍是两份独立副本，无运行时共享收益，反而引入跨目录相对引用，触碰共享叶子的零引用约束。

### 两包自持、评审保证同构（被采纳）

两处实现各自保留，文件头注明同构关系与同步义务：改任一处须同步另一处。跨文件一致性不由门禁覆盖，由评审保证；退役的根共享实现不再恢复。

## Consequences

- 收益：公开导出面零变化（两包各自的默认注入与命名保持）；共享叶子约束零触碰（无跨目录值引用，无整转出禁用违规）；构建产物形状不变（各自内联，无包外运行时引用残留）。
- 代价：算法变更要改两处，漏同步即行为分叉；评审必须把另一份实现纳入必查清单。代价可控：函数为纯函数且有单测与 smoke 断言分支翻转，漏同步会被用例点名。
